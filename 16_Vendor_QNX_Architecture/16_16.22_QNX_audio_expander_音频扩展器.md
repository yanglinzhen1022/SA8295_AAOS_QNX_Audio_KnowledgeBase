# 16.22 audio_expander — QNX 侧 I2C 音频扩展器（DAC 使能/音源开关）

> [前篇：16.21 audio_dac](16_16.21_QNX_audio_dac_DAC音频驱动.md) · [本章导航](README.md) · [收束：16.12 双域架构总结](16_16.12_Android+QNX双域架构总结.md) · [总导航](../README.md)

> 定位：`audio_expander` 与 [audio_dac](16_16.21_QNX_audio_dac_DAC音频驱动.md) 是**一对**：都在 `Qnx/apps/qnx_ap/AMSS/multimedia/audio/audio_common/` 下、同一套 "单例 + 句柄表 + I2C 读写" 骨架（`aud_*` 前缀对应 `dac_*`），都只服务 QNX 侧硬件板级控制。区别在受控对象：expander 控制的是 **I2C I/O 扩展器**（寄存器 0x00~0x07 的两端口 I/O 布局），管 **DAC 供电、爆音抑制、TDM 音源选择（SoC vs Mercury）**。

## 16.22.1 API 与结构（与 audio_dac 同构）

五个 API：`audio_expander_init/open/ioctl/close/deinit`；ioctl 三个命令（`audio_expander.h`）：`CMD_SET_DAC_ENABLE (0x2001)`、`CMD_SET_SWITCH_SOURCE (0x2002)`、`CMD_SET_SWITCH_ENABLE (0x2003)`。结构与 init 逻辑和 audio_dac 几乎逐行对应：

```c
typedef struct audio_expander_main {
    uint32_t ref_cnt;
    uint32_t reserved;
    int32_t i2c_fd;
    uint16_t slave_addr;
} audio_expander_main_t;
```

> 源码：`Qnx/apps/qnx_ap/AMSS/multimedia/audio/audio_common/audio_expander/src/audio_expander.c`（单例 `static audio_expander_main_t audio_expander_main`；`audio_expander_init()` 同样打开 `/dev/i2c%u`、`aud_handle_init(16)` 建 16 句柄表、ref_cnt 防重入）

寄存器表是典型两端口 I/O 扩展器布局：

```c
#define REG_INPUT_PORT_0 										0x00
#define REG_INPUT_PORT_1 										0x01
#define REG_OUTPUT_PORT_0 									0x02
#define REG_OUTPUT_PORT_1 									0x03
#define REG_POLARITY_INVERSION_PORT_0 			0x04
#define REG_POLARITY_INVERSION_PORT_1 			0x05
```

> 源码：`audio_expander.c`。其后 `REG_CONFIGURATION_PORT_0/1 (0x06/0x07)` 的注释说明：默认端口为输入高阻，对应位清 0 才是输出。源码未标注具体芯片型号。

引脚位定义（Port 0）——这是理解三个命令的钥匙：

- `PORT_0_DAC_SELECT_PIN_BIT (1<<3)`：**音源选择**，`1 Mercury → DAC；0 SoC → DAC`；
- `PORT_0_DAC_CLICK_POP_MUTE_PIN_BIT (1<<5)`：爆音/静音电路；
- `PORT_0_DAC_ENABLE_PIN_BIT (1<<6)`：DAC 供电；
- `PORT_0_TDM_MUX_PIN_BIT (1<<7)`：DAC Switch，**`0 使能；1 禁止`**（低有效，注释原文如此）。

## 16.22.2 三个命令做什么

**CMD_SET_DAC_ENABLE**：读 CONFIGURATION_PORT_0/OUTPUT_PORT_0 两寄存器，`enable=true` 时把两位（供电、爆音抑制）从配置寄存器清 0（变输出）并在输出寄存器置 1；`false` 反向（置高阻、输出清 0）。

**CMD_SET_SWITCH_SOURCE**：只改 OUTPUT_PORT_0 的 `DAC_SELECT` 位：

```c
    output_port0_reg_data = read_data[0];
    if (source_param->src == SOC_AUDIO)
    {
        output_port0_reg_data &= ~PORT_0_DAC_SELECT_PIN_BIT;
    }
    else
    {
        output_port0_reg_data |= PORT_0_DAC_SELECT_PIN_BIT;
    }
```

> 源码：`audio_expander.c` `audio_expander_set_switch_source()`。`src` 枚举（`audio_expander.h`）：`SOC_AUDIO = 0x1000 /*SoC MI2S0 output*/`、`MERCURY_AUDIO /*Mercury TDM output*/`——选择 SoC 的 MI2S 还是 Mercury 板的 TDM 送进 DAC

**CMD_SET_SWITCH_ENABLE**：同时操作 `TDM_MUX` 与 `DAC_SELECT` 两个位——`enable=false` 时两位置 1（开关断开 + 音源切走），`true` 时清 0（开关接通）。低有效语义下这是 "断电前先断信号路径" 的保护顺序，但**源码只写位，不解释意图**，此句是读者视角的理解。

## 16.22.3 AR 主线消费者（与 16.21 相同的两处）

**消费者 1：`csd2_dev_oem_lib`**——开机顺序即语义顺序：先 `CMD_SET_DAC_ENABLE(true)`（供电），再 `CMD_SET_SWITCH_ENABLE(true)`（接通），再 `CMD_SET_SWITCH_SOURCE(SOC_AUDIO)`（选 SoC 音源），`usleep(100*1000)` 等 DAC 稳定后才去初始化 PCM1681：

```c
    step = 2;
    enable_payload_t.enable = true;
    rc = audio_expander_ioctl(io_handle, CMD_SET_DAC_ENABLE,
            &enable_payload_t, sizeof(dac_enable_t));
    if (AUD_EOK != rc)
        goto exit;

    step = 3;
    switch_payload_t.enable = true;
    rc = audio_expander_ioctl(io_handle, CMD_SET_SWITCH_ENABLE,
            &switch_payload_t, sizeof(switch_enable_t));
    if (AUD_EOK != rc)
        goto exit;

    step = 4;
    switch_source_t.src = SOC_AUDIO;
    LOG(QCLOG_INFO,"TDM source 0x%0x",switch_source_t.src);
    rc = audio_expander_ioctl(io_handle, CMD_SET_SWITCH_SOURCE,
            &switch_source_t, sizeof(switch_source_t));
    if (AUD_EOK != rc)
        goto exit;

    usleep(100*1000);//sleep 60ms to wait DAC into steady state
```

> 源码：`Qnx/apps/qnx_ap/AMSS/multimedia/audio/audio_ar/audio_driver/csd2_dev_oem_lib/cdc_oem/cdc_dev_oem_plugin.c`（步骤 2-4；expander 用 i2c4、地址 0x77。注释 "sleep 60ms" 与实际 `100*1000` 微秒不一致——如实记录）

**消费者 2：`csd2_ipc/audio_chime`（QNX 侧 chime）**——`audio_chime_set_audio_output(source)` 用 `CMD_SET_SWITCH_SOURCE` 在 `SOC_AUDIO`（"DAC"）与 `MERCURY_AUDIO`（"Mercury"）之间切输出，用完即 close+deinit。这是 QNX 侧音源切换的真实调用点。

## 16.22.4 边界与常见误读

| 维度 | 源码事实 |
|---|---|
| 芯片型号 | 源码**未标注**；不要写成具体型号（寄存器布局只是"像"某类两端口扩展器） |
| 与 audio_dac 的关系 | 同骨架、同目录族、同一批消费者；但对象不同（I/O 扩展器 vs DAC），命令集不同 |
| 线程安全 | 无锁；ref_cnt 只防重复 init |
| SSR | 无 |
| 硬编码 | 消费者侧 i2c 设备号 4、地址 0x77（expander）/0x4C（DAC）写在调用方，不在库内；`audio_expander.h` 编辑史注 "for BRAC" |
| 链接名 | 模块 `NAME=audio_expander`（Makefile）；AR 消费者以 `-laudio_expanderS` 链接（common.mk） |

| 层次 | 能证明 | 不能证明 |
|---|---|---|
| 源码/构建 | API、寄存器语义、AR 调用点（含顺序与参数） | — |
| 部署 | — | 扩展器芯片实际在位、i2c4/0x77 是哪块板 |
| 运行 | — | 开机链是否执行成功、Mercury 音源何时被选中、真实信号路径 |

## 本节小结

expander 回答 "DAC 的电和信号从哪来"：供电、开关、音源三个位，开机链按 供电→开关→音源 的顺序摆好，chime 自检还能临时切到 Mercury。和 16.21 合起来，这对库展示了 QNX 域如何用最小的 I2C 封装管理板级音频硬件——以及为什么这类硬件细节永远不该写进 Android 域的文档。
