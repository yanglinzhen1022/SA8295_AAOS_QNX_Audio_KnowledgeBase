# 16.21 audio_dac — QNX 侧 PCM1681 DAC 控制（I2C）

> [前篇：16.20 a2b 兼容入口](16_16.20_QNX_audio_a2b_A2B总线音频.md) · [本章导航](README.md) · [后篇：16.22 audio_expander 音频扩展器](16_16.22_QNX_audio_expander_音频扩展器.md) · [总导航](../README.md)

> 定位：`audio_dac` 是 **audio_common** 下的 QNX 用户态库（有源码，非预编译），通过 I2C 控制外部 **PCM1681**（8 通道 DAC）的静音、格式与默认增益。它被 AR 主线的两个消费者使用：`csd2_dev_oem_lib`（开机初始化链）与 `csd2_ipc/audio_chime`（QNX 侧 chime 自检/输出切换）。它**不是** resmgr、**没有** SSR/事件机制——就是 "I2C 寄存器读写 + 句柄管理" 的小库。

## 16.21.1 API 与对象模型

五个对外 API（`audio_dac.h`）与三层对象（模块单例/上下文/句柄表）：

```c
typedef struct audio_dac_main {
    uint32_t ref_cnt;
    uint32_t reserved;

    int32_t i2c_fd;
    uint16_t slave_addr;
} audio_dac_main_t;

typedef struct audio_dac_context {
    uint32_t handle;
    audio_dac_main_t *glb;
    uint32_t reserved;
} audio_dac_context_t;
```

> 源码：`Qnx/apps/qnx_ap/AMSS/multimedia/audio/audio_common/audio_dac/src/audio_dac.c`（Typedef 节，单例 `static audio_dac_main_t audio_dac_main`）

- `audio_dac_init(init_cfg)`：单例初始化。打开 `/dev/i2c%u`（`init_cfg->i2c_device`），记录 `i2c_addr`，`dac_handle_init(16)` 建句柄表，然后**只对 DAC1~DAC4**（`REG_DAC1_AT..REG_DAC4_AT`）写默认增益 `dac_default_gain = 224`。`ref_cnt > 1` 时直接返回 EOK（不重复开 I2C）。
- `audio_dac_open(&handle)`：分配 context，从句柄表领 handle，`glb` 指向单例。
- `audio_dac_ioctl(handle, cmd, param, len)`：仅两个命令 `CMD_SET_DAC_MUTE (0x1001)` / `CMD_SET_DAC_FMT (0x1002)`，其余 `unsupported ioctl cmd` 返回 EBADPARAM。
- `audio_dac_close` / `audio_dac_deinit`：close 释放 context+handle；deinit 按 ref_cnt 递减，最后一个才 `i2c_close`。

```c
    snprintf(fn, sizeof(fn), "/dev/i2c%u", init_cfg->i2c_device);
    audio_dac_main.i2c_fd = i2c_open(fn);
    if (-1 == audio_dac_main.i2c_fd)
    {
        DAC_MSG(DAC_PRIO_ERROR,"i2c open failure");
        rc = DAC_EFAILED;
        goto end;
    }
    audio_dac_main.slave_addr = init_cfg->i2c_addr;

    rc = dac_handle_init(16);
    if (DAC_EOK != rc)
    {
        DAC_MSG(DAC_PRIO_ERROR,"initial handle failure");
        i2c_close(audio_dac_main.i2c_fd);
        rc = DAC_EFAILED;
        goto end;
    }

    for (dac_idx = REG_DAC1_AT; dac_idx <= REG_DAC4_AT; dac_idx++)
        (void)audio_dac_set_default_gain(&audio_dac_main, dac_idx, dac_default_gain);
```

> 源码：`audio_dac.c` `audio_dac_init()`。注意默认增益**只写前 4 个 DAC 通道**（寄存器 0x01~0x04），且返回值被丢弃——写失败不影响 init 成功。

## 16.21.2 寄存器语义（PCM1681）

```c
enum pcm1681_reg_map {
    RESERVED_REG_0 	=  	0x0,
    /*Digital attenuation control for DAC1, default 0 dB, no attenuation*/
    REG_DAC1_AT		 	=  	0x01,
    REG_DAC2_AT    	= 	0x02,
    REG_DAC3_AT    	=  	0x03,
    REG_DAC4_AT			=	0x04,
    REG_DAC5_AT			=	0x05,
    REG_DAC6_AT			=	0x06,

    REG_DAC_MUTE		= 	0x07, /*mute DAC1~8 base each bit value. default 0 , unmute state*/
    REG_DAC_OPERATION	= 0x08,/*DAC1~DAC8 enable control, default, enabled*/
    REG_DAC_FORMAT	=		0x09,	/*FMT[3:0]*/

    REG_DAC_SW_RESET = 0xA, /*BIT7*/

    REG_DAC_AT_MODE = 0xD, /*DAMS bit decide attenuation mode*/
};
```

> 源码：`audio_dac.c`（`pcm1681_reg_map`；注释注明 0x01~0x06 是数字衰减控制、0x07 是按位静音）

增益注释 `129 (-63dB) ~ 255 (0dB)` / `0 ~ 128 mute` 给出刻度锚点（默认 224 落在两点之间；具体 dB 换算源码未写）。两个 ioctl 的实现：

- `audio_dac_set_mute`：读 REG_DAC_MUTE → `mute? 0xff（全通道静音）: 0x0（全开）` → 写回。只有全开/全静音两种，**没有按通道静音的对外命令**。
- `audio_dac_set_format`：读 REG_DAC_FORMAT → 清 B0~B3 → `I2S_TDM|=0x6` / `LEFT_JUSTIFIED_TDM|=0x7`，其他格式直接 EFAILED。

## 16.21.3 谁在用它（AR 主线证据）

**消费者 1：`csd2_dev_oem_lib`（开机硬件初始化链）**。`csd2_dev_oem_init()` 先配 expander（见 [16.22](16_16.22_QNX_audio_expander_音频扩展器.md)），再初始化 DAC：

```c
    dac_init_cfg.i2c_device = 4;
    dac_init_cfg.i2c_addr = 0x4C;
    rc = audio_dac_init(&dac_init_cfg);
    rc |= audio_dac_open(&dac_handle);
    if (AUD_EOK != rc)
        goto exit;

    step = 6;
    fmt_t.format = I2S_TDM;
    rc = audio_dac_ioctl(dac_handle, CMD_SET_DAC_FMT,
            &fmt_t, sizeof(fmt_payload_t));
    if (AUD_EOK != rc)
        goto exit;
    LOG(QCLOG_INFO,"audio_expander_dac intialization success");
```

> 源码：`Qnx/apps/qnx_ap/AMSS/multimedia/audio/audio_ar/audio_driver/csd2_dev_oem_lib/cdc_oem/cdc_dev_oem_plugin.c`（步骤 5-6：i2c4/0x4C，I2S_TDM 格式；成功后继续 dlopen `libMercuryApp.so`）

**消费者 2：`csd2_ipc/audio_chime`（QNX 侧 chime 自检）**——`audio_chime_dac_test()` 循环 10 次翻转 `CMD_SET_DAC_MUTE`（每次 `usleep(2000*1000)`）。QNX chime 与 Android 侧 `audio_chime_app`（[16.5](16_16.5_audio-chime早期提示音.md)）**是两个不同程序**，别混写。

## 16.21.4 边界与常见误读

| 维度 | 源码事实 |
|---|---|
| 库形态 | 用户态静态库 `libaudio_dacS`（common.mk 链接名），无 resmgr/dispatch |
| 用途标注 | 版权头 2020-2021 Qualcomm；`audio_dac.h` 编辑史注 "initial implementation for audio_dac module for **BRAC**"，注释 "pcm1681 control" |
| 单例性 | `static audio_dac_main` 全局单例；ref_cnt 防重入，但**多线程无锁** |
| SSR | 无任何恢复逻辑；I2C 失败只返回错误码 |
| 音量 | 无对外音量 cmd；默认增益 224 仅在 init 时写 DAC1~4 |

| 层次 | 能证明 | 不能证明 |
|---|---|---|
| 源码/构建 | API、寄存器操作、AR 消费者链接与调用点 | — |
| 部署 | — | 目标机是否真的接了 PCM1681、i2c4 是否存在 |
| 运行 | — | init 是否执行过、寄存器写入是否到达硬件、实际输出电平 |

## 本节小结

audio_dac 把 "外部 DAC 怎么被 SoC 控制" 浓缩成两个 I2C 命令（静音/格式）加一次性默认增益。它依赖上游（expander 先开、chime/dev_oem 调用）才有意义——单独读这个库不会知道 DAC 何时发声。下一节的 audio_expander 正是它的上游"开关矩阵"。
