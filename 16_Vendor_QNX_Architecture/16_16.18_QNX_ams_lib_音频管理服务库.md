# 16.18 旧 AMS 主题的兼容入口与当前图管理路线

> [前篇：AR 服务](16_16.17_QNX_audio_service_vm_VM音频服务.md) · [本章导航](README.md) · [后篇：GPR 传输](16_16.19_QNX_apr_lib_APR协议库.md) · [总导航](../README.md)

本页保留 ams_lib 历史文件名。旧文主体来自 Elite 目录；当前知识库只研究本地 Android 12L + SA8295 + QNX **AudioReach**，不继续把该库放进 `AGM → gsl_vm_be → ams_lib → DSP` 的错误主链，也不将旧 AMS 的接口、状态和 TDM 枚举直接套给当前图管理。

## 当前应该区分的三个入口

| 层次 | 当前主线的对象与接口 | 正文 |
|---|---|---|
| Android 会话与音频图 | AGM 的 session_obj、graph_obj、metadata/AIF；PAL 经插件或 AGM API 进入 | [18.1 AGM](../18_AGM_GSL_Architecture/18_18.1_AGM会话与音频图.md) |
| QNX 宿主 GSL | handle、GKV node、共享 SG、GPR 控制与 buffer 完成 | [18.3 GSL](../18_AGM_GSL_Architecture/18_18.3_GSL图生命周期与DSP命令.md) |
| QNX CSD2 的服务接入 | AR service 启动 CSD2 IPC，并用 CSD2 SSR 客户端注册；CGM 内有本地 GSL 初始化 | [16.17 服务编排](16_16.17_QNX_audio_service_vm_VM音频服务.md)、[16.6 校准初始化](16_16.6_ACDB校准体系.md) |

这些不是三个同义“音频管理器”，也不因都含 session/graph 就共享同一种 handle。AGM 的会话 ID、CSD2 的模块 handle、GSL 的不透明 graph handle，以及 DSP 的 SGID/MIID 应按调用边界分别追踪。

## CSD2 的可见范围

[csd2_api.c](../../Qnx/apps/qnx_ap/AMSS/multimedia/audio/audio_ar/audio_driver/csd2/src/csd2_api.c) 展示公共 init/open/ioctl 等入口和模块函数表；[csd2_cgm.c](../../Qnx/apps/qnx_ap/AMSS/multimedia/audio/audio_ar/audio_driver/csd2/modules/session/stream/src/csd2_cgm.c) 的 `csd2_cgm_init()` 组装初始数据库信息并调用 `gsl_init()`。这提供了当前 AR 的明确代码落点，而不是“AMS 改名成 CSD2”的历史推测。

本页不替代 CSD2 所有设备、时钟、session 和 SSR 模块的完整教材。已有正文覆盖其服务接入及 GSL/校准边界；进一步研究时，应从具体 CSD2 调用追到模块分发，而不是把另一架构的图 API 复制过来。原文的非主线细节由版本历史保留，读者主线不再展开。

若问题是“为什么停止一条流不一定停止共享设备图”，读 [18.3 的 SG 引用计数](../18_AGM_GSL_Architecture/18_18.3_GSL图生命周期与DSP命令.md)；若问题是“Android 退出后 QNX 怎样清理”，读 [18.2 的 VM 会话清理](../18_AGM_GSL_Architecture/18_18.2_GSL跨VM控制与缓冲区.md)。不要用旧 AMS 状态图替代这两种不同机制。
