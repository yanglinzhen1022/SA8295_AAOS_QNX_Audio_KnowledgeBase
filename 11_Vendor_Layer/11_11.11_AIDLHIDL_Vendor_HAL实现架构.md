### 11.11.1 架构总览（12L 本树事实）

> **版本边界（负结论）**：Android 14 的 AIDL 音频 HAL（`hardware/interfaces/audio/aidl` 的 `IModule.aidl`/`IConfig.aidl`、framework 侧 `DevicesFactoryHalAidl.cpp`）**不在本树**。本树（Android 12L）音频 HAL 主线是 **HIDL**：接口定义 `hardware/interfaces/audio/7.0/`（2.0→7.0 均存在），framework 桥接层在 `frameworks/av/media/libaudiohal/impl/`，默认参考实现在 `hardware/interfaces/audio/core/all-versions/default/`。产品（msmnile_gvmq/msmnile_au）实际打包到 **audio@6.0**（见 11.11.5）。

### 11.11.3 DevicesFactoryHalHybrid 关键实现（12L）

[`openDevice`](frameworks/av/media/libaudiohal/impl/DevicesFactoryHalHybrid.cpp:32) 决定走 HIDL 还是本地直连：

```cpp
status_t DevicesFactoryHalHybrid::openDevice(const char *name, sp<DeviceHalInterface> *device) {
    if (mHidlFactory != 0 && strcmp(AUDIO_HARDWARE_MODULE_ID_A2DP, name) != 0 &&
        strcmp(AUDIO_HARDWARE_MODULE_ID_HEARING_AID, name) != 0) {
        return mHidlFactory->openDevice(name, device);
    }
    return mLocalFactory->openDevice(name, device);
}
```

> 源码：`DevicesFactoryHalHybrid.cpp:32-38`（逐字摘录，12L）。**规则**：除 A2DP 与 HearingAid 两个模块名外，其余模块（含 `primary`/`r_submix`/`usb` 及自定义模块）一律走 HIDL 工厂；A2DP/HearingAid 因需要与 bluetooth 进程内协作，使用 **Local 直连**（`dlopen` 本地 so）。`getHalPids()`/`setCallbackOnce()` 只有 HIDL 通路（:40-52）。

### 11.11.4 HIDL vs AIDL 演进对比（AIDL 列为版本坐标）

| 维度 | HIDL（12L 本树） | AIDL（13+/14，不在本树） |
|------|----------------|------------------------|
| 接口定义 | `hardware/interfaces/audio/7.0/*.hal` | `hardware/interfaces/audio/aidl/.../IModule.aidl` |
| factory | `IDevicesFactory.hal`，Hybrid 桥接 | `IFactory`，按 name 实例化 IModule |
| 版本管理 | 2.0→7.0 多版本共存 | aidl_api 版本目录（1/2/3…） |
| 流方向 | IStreamOut/IStreamIn 显式类型 | IStreamIn/Out 拆分 + BufferDescriptor/FMQ 统一 |
| 音量 | master volume + per-stream setVolume | per-device volume 曲线（sounddose/核心配置） |
| SoundDose | 无（见 [13.5](../13_Volume_Device_Deep_Dive/13_13.5_SoundDose与CSD声剂量管理.md)） | ISoundDose 接口（14） |
| BLuetooth A2DP offload | Local 直连（见 11.11.3） | 纳入 IModule 标准能力 |

### 11.11.5 本产品的 HAL 打包证据（msmnile_au / msmnile_gvmq）

- `msmnile_au.mk:469-500`（vendor/qcom/opensource/audio-hal-ar/primary-hal/configs/）：`PRODUCT_PACKAGES` 打包 `android.hardware.audio@2.0-service`、`@2.0-impl`，并逐级追加 `@4.0`、`@5.0`、`@6.0` 的 `-impl` 与 `android.hardware.audio.common@N.0(-util)`、`android.hardware.audio.effect@N.0-impl`。
- `device/qcom/msmnile_gvmq/msmnile_gvmq.mk:315-320`：Guest 侧同样打包 `android.hardware.audio@5.0-impl` 系列。
- Primary HAL 实现本体是 AR 版 `audio.primary.msmnile.ar`（PAL→AGM/GSL→QNX audio_service 链路，详见 [16.13](../16_Vendor_QNX_Architecture/16_16.13_Primary_HALAudioReach版深度解.md)），通过 HIDL `@6.0-impl` 对 framework 暴露；`android.hardware.audio@7.0` 接口虽在本树 hardware/interfaces 中定义，产品 mk 未打包 7.0-impl。

### 11.11.6 Vendor参数扩展实战（HIDL setParameters 路径）

12L 的 vendor 扩展通道是 [`IDevice.setParameters`](hardware/interfaces/audio/7.0/IDevice.hal:302)（`setParameters(vec<ParameterValue> context, vec<ParameterValue> parameters)`），AR HAL 侧由 `AudioDevice.cpp` 的 `adev_set_parameters` 落到 PAL `ResourceManager`（详见 [16.13](../16_Vendor_QNX_Architecture/16_16.13_Primary_HALAudioReach版深度解.md)）。AIDL 时代的 `VendorParameter`/`setParameter` 回调式扩展不在本树。
