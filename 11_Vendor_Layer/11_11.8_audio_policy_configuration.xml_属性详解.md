### 11.8.1 文档结构总览

audio_policy_configuration.xml是Audio Policy系统的核心配置文件，定义了音频硬件模块、设备端口、混音端口和路由关系。本文档对所有XML标签和属性进行方法级详解。

```mermaid
graph TD
    Root[audioPolicyConfiguration] --> Global[globalConfiguration]
    Root --> Modules[modules]
    Modules --> Module[module]
    Module --> Attached[attachedDevices]
    Module --> DefaultDev[defaultOutputDevice]
    Module --> MixPorts[mixPorts]
    Module --> DevPorts[devicePorts]
    Module --> Routes[routes]
    MixPorts --> MixPort[mixPort]
    MixPort --> Profile[profile]
    DevPorts --> DevPort[devicePort]
    DevPort --> Profile2[profile]
    DevPort --> Gains[gains]
    Gains --> Gain[gain]
    Routes --> Route[route]
    Root --> VolInc[xi:include volumes]

    style Root fill:#e3f2fd
    style Module fill:#e8f5e9
    style MixPort fill:#fff3e0
    style DevPort fill:#fce4ec
```

### 11.8.2 根节点 audioPolicyConfiguration

| 属性 | 必填 | 类型 | 说明 |
|------|------|------|------|
| version | 是 | string | 配置版本号，格式major.minor |

**版本演进**：

> **勘误（负结论）**：解析器仅接受 `version="1.0"` 或 `"7.0"`（Serializer.cpp:864-870），**不存在 version=2.0**；7.0 的唯一语义是把 channelMasks/samplingRates/flags 分隔符改为**空格**（:864-865），与 AIDL HAL 无关。`call_screen_mode_supported` 在 1.0 下同样解析（Serializer.cpp:758-762）。

| 版本 | 对应Android版本 | 关键变更 |
|------|-----------------|----------|
| 1.0 | 本树产品/cuttlefish/emulator 均为 1.0（版本引入史非本树源码可证） | 基础设备/路由定义；分隔符 flags=`|`、采样率/mask=`,`（Serializer.cpp:249-251） |
| 7.0 | 引入空格分隔 | channelMasks/samplingRates/flags 改为空格分隔（唯一语义差异） |

**参考设备示例**（cuttlefish，[`audioPolicyConfiguration`](device/google/cuttlefish/shared/auto/audio_policy_configuration.xml:24)）：
```xml
<audioPolicyConfiguration version="1.0" xmlns:xi="http://www.w3.org/2001/XInclude">
```
（本树 `device/google/` 下无 redfin；device/google 下根元素版本均为 1.0，device/generic/goldfish 为 `version="7.0"`（树内 7.0 实例）；HAL 版本在 `<module halVersion>` 中声明。）

**Car端示例**（[`audioPolicyConfiguration`](device/generic/car/emulator/audio/audio_policy_configuration.xml:17)）：
```xml
<audioPolicyConfiguration version="1.0" xmlns:xi="http://www.w3.org/2001/XInclude">
```

### 11.8.3 globalConfiguration 全局配置

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| speaker_drc_enabled | bool | false | 扬声器DRC（动态范围压缩）开关 |
| call_screen_mode_supported | bool | false | 通话屏幕模式支持（引入版本史非本树源码可证；本树无配置设置） |

**Phone端示例**（上游/示意——本树 device/ 配置未设置 call_screen_mode_supported）：
```xml
<globalConfiguration speaker_drc_enabled="true" call_screen_mode_supported="true"/>
```

**Car端示例**：
```xml
<globalConfiguration speaker_drc_enabled="true"/>
```

**speaker_drc_enabled解析（12L 边界）**：
- 解析后仅存入 AudioPolicyConfig（AudioPolicyConfig.h:111-115；Serializer.cpp:753-757）
- **本树无消费点**：`isSpeakerDrcEnabled` 在 frameworks/av 仅定义处命中（AudioPolicyConfig.h:111-115），无调用点；"AudioFlinger::PlaybackThread 检查 mGlobalConfig" 的机制在本树不存在
- 属性本身可配置

**call_screen_mode_supported解析（12L 边界）**：
- 存入 AudioPolicyConfig（成员 :232）并经查询链暴露：APM `isCallScreenModeSupported()`（AudioPolicyManager.cpp:4789）→ AudioPolicyService binder（AudioPolicyInterfaceImpl.cpp:2046）→ AudioSystem/JNI（AudioSystem.cpp:2100、android_media_AudioSystem.cpp:2530）；但**无策略消费路径**（engine 无 CALL_SCREEN 策略）
- 本树 device/ 与 frameworks 配置中 0 设置（属性受解析器支持，:758-762）

### 11.8.4 module 模块节点

module代表一个Audio HAL实现，每个HAL对应一个module。

| 属性 | 必填 | 类型 | 说明 |
|------|------|------|------|
| name | 是 | string | 模块名，决定加载哪个HAL库 |
| halVersion | 否 | string | HAL版本号，格式major.minor（缺省 0.0） |

**name属性取值表**：

| name | HAL库文件 | 说明 |
|------|-----------|------|
| primary | audio.primary.*.so | 主音频HAL，必需 |
| a2dp | audio.a2dp.*.so | 蓝牙A2DP HAL |
| usb | audio.usb.*.so | USB音频HAL |
| r_submix | audio.r_submix.*.so | 远程子混音HAL |
| bluetooth_qti | audio.bluetooth_qti.*.so | QC 蓝牙HAL（本树配置实名，configs/common/bluetooth_qti_*.xml；hearing_aid 变体亦用 bluetooth_qti，AU 产品未安装 hearing_aid 配置） |
| stub | audio.stub.*.so | 空实现HAL（模拟器用） |

**halVersion对应关系（12L 本树事实）**：

| halVersion | HAL接口类型 | 说明 |
|------------|------------|------|
| 2.0/4.0/5.0/6.0/7.0 | HIDL（hardware/interfaces/audio 实际存在的版本目录） | 7.0 为最新 |
| 3.0 | 版本对声明（HIDL 语义） | car emulator `halVersion="3.0"`（emulator:51）；树中**无** 3.0 接口目录，Serializer.cpp:665-672 仅 sscanf 解析数值对（sscanf :669），"Android 11 扩展 HAL"之说无依据 |
| AIDL（IModule） | AIDL | **Android 13+，不在本树**（本树无 audio .aidl） |

（halVersion 属性本身可省略，:665-672 缺省时取默认 0.0。）

**Phone端primary模块**：
```xml
<module name="primary" halVersion="2.0">
```

**Car端primary模块**：
```xml
<module name="primary" halVersion="3.0">
```

### 11.8.5 attachedDevices 永久附加设备

列出物理上永久连接的设备，这些设备不可热插拔。

```xml
<attachedDevices>
    <item>Speaker</item>           <!-- Phone端：扬声器 -->
    <item>Earpiece</item>          <!-- Phone端：听筒 -->
    <item>Built-In Mic</item>      <!-- 内置麦克风 -->
</attachedDevices>
```

**Car端典型配置**（[`module primary`](device/generic/car/emulator/audio/audio_policy_configuration.xml:51)，attachedDevices 实际列表 :52-72 节选+中文注解，非逐字摘录）：
```xml
<attachedDevices>
    <item>bus0_media_out</item>
    <item>bus1_navigation_out</item>
    <item>bus2_voice_command_out</item>
    <item>bus3_call_ring_out</item>
    <item>bus4_call_out</item>
    <item>bus5_alarm_out</item>
    <item>bus6_notification_out</item>
    <item>bus7_system_sound_out</item>
    <item>bus100_audio_zone_1</item>
    <item>bus200_audio_zone_2</item>
    <item>Built-In Mic</item>
    <item>Built-In Back Mic</item>
    <item>Echo-Reference Mic</item>
    <item>FM Tuner</item>
    <item>Tone Generator 0</item>
    <item>Tone Generator 1</item>
</attachedDevices>
```

**关键约束**：
- item值必须与devicePort的tagName完全匹配
- 未在attachedDevices中的设备被视为可移除设备（如USB、蓝牙）
- Car端所有Bus设备均为attachedDevices

### 11.8.6 defaultOutputDevice 默认输出设备

当AudioPolicy无法根据策略路由时使用的默认设备。

```xml
<defaultOutputDevice>Speaker</defaultOutputDevice>  <!-- Phone -->
<defaultOutputDevice>bus0_media_out</defaultOutputDevice>  <!-- Car -->
```

**约束（惯例）**：defaultOutputDevice 应指向已声明的 devicePort tagName（解析器仅要求 tagName 匹配 devicePort，Serializer.cpp:730-732；"必须在 attachedDevices 中列出"为惯例约束，解析器不校验）。

### 11.8.7 mixPort 混音端口详解

mixPort定义音频流端点，代表AudioFlinger与HAL之间的数据通道。

#### 11.8.7.1 mixPort完整属性表

> **勘误（负结论）**：原表 `maxOpenSessionsCount`/`maxActiveSessionsCount`/`preferredMixDevice` 均非本树属性（MixPortTraits 仅 name/role/roleSource/flags/maxOpenCount/maxActiveCount，Serializer.cpp:113-129、属性 :118-126；三个假名 audiopolicy 全树零命中）。真实属性：

| 属性 | 必填 | 类型 | 说明 | 示例 |
|------|------|------|------|------|
| name | 是 | string | 端口标识名，route引用用此名 | primary output |
| role | 是 | enum | source=输出流，sink=输入流 | source |
| flags | 否 | string | AUDIO_OUTPUT_FLAG_*组合，version=1.0 下 `\|` 分隔 | AUDIO_OUTPUT_FLAG_PRIMARY\|AUDIO_OUTPUT_FLAG_FAST（产品 common_au:96） |
| maxOpenCount | 否 | int | 最大同时打开数 | 1 |
| maxActiveCount | 否 | int | 最大活跃数（输入/输出 mixPort 双角色均解析，Serializer.cpp:491-498；0=无限制） | 1 |

#### 11.8.7.2 输出flags详解与Thread映射

数值按 audio-hal-enums.h:423-440 修正（Thread 类型为 12L 真实类，FAST/DEEP_BUFFER 均为 MixerThread 内嵌机制，无独立类）：

| flags值 | 值(int) | Thread类型 | 延迟 | 说明 |
|---------|---------|-----------|------|------|
| AUDIO_OUTPUT_FLAG_DIRECT | 0x1 | DirectOutputThread | ~20ms | 不混音直接输出 |
| AUDIO_OUTPUT_FLAG_PRIMARY | 0x2 | MixerThread | ~20ms | 系统主输出，唯一 |
| AUDIO_OUTPUT_FLAG_FAST | 0x4 | MixerThread（fast track） | <10ms | 超低延迟，触摸反馈 |
| AUDIO_OUTPUT_FLAG_DEEP_BUFFER | 0x8 | MixerThread（普通track） | ~50ms | 长缓冲高吞吐 |
| AUDIO_OUTPUT_FLAG_COMPRESS_OFFLOAD | 0x10 | OffloadThread | N/A | 硬件解码不混音 |
| AUDIO_OUTPUT_FLAG_NON_BLOCKING | 0x20 | （offload 配套） | N/A | 非阻塞 |
| AUDIO_OUTPUT_FLAG_HW_AV_SYNC | 0x40 | — | N/A | HW AV 同步 |
| AUDIO_OUTPUT_FLAG_TTS | 0x80 | — | N/A | TTS |
| AUDIO_OUTPUT_FLAG_RAW | 0x100 | — | <10ms | 原始数据直传 |
| AUDIO_OUTPUT_FLAG_SYNC | 0x200 | — | N/A | 同步 |
| AUDIO_OUTPUT_FLAG_IEC958_NONAUDIO | 0x400 | — | N/A | IEC958 非音频（压缩直通） |
| AUDIO_OUTPUT_FLAG_DIRECT_PCM | 0x2000 | — | N/A | PCM 直通 |
| AUDIO_OUTPUT_FLAG_MMAP_NOIRQ | 0x4000 | MmapPlaybackThread | <5ms | AAudio MMap模式 |
| AUDIO_OUTPUT_FLAG_VOIP_RX | 0x8000 | — | ~10ms | VoIP接收专用（产品 common_au 使用） |
| AUDIO_OUTPUT_FLAG_INCALL_MUSIC | 0x10000 | — | N/A | 通话中上行音乐 |
| AUDIO_OUTPUT_FLAG_GAPLESS_OFFLOAD | 0x20000 | OffloadThread | N/A | 无缝播放Offload |

**flags分隔与组合（12L 解析器真实行为）**：
- version=1.0 时 flags 以 `|` 分隔（mFlagsSeparator="|"，Serializer.cpp:249-251）；**空格分隔仅 version=7.0**。1.0 下写空格分隔的 flags 会整串查表失败被静默丢弃（flags=0，TypeConverter.h:182-195 strtok 单分隔符）。产品实写示例：`flags="AUDIO_OUTPUT_FLAG_PRIMARY|AUDIO_OUTPUT_FLAG_FAST"`（common_au:96）
- "PRIMARY和DEEP_BUFFER互斥""COMPRESS_OFFLOAD必须同时指定DIRECT"为惯例约定，解析器不校验

**参考设备典型mixPort配置**（cuttlefish，[`primary output`](device/google/cuttlefish/shared/auto/audio_policy_configuration.xml:35)，该文件 mixPort 仅此两个+primary input，逐字摘录、统一去除前导缩进）：
```xml
<mixPort name="primary output" role="source" flags="AUDIO_OUTPUT_FLAG_PRIMARY">
    <profile name="" format="AUDIO_FORMAT_PCM_16_BIT"
        samplingRates="44100" channelMasks="AUDIO_CHANNEL_OUT_STEREO"/>
</mixPort>
<mixPort name="primary input" role="sink">
```

> **勘误**：原摘录把 cuttlefish 锚点与产品配置的 deep_buffer/compressed_offload 段拼接改写，非该文件真实内容。产品**生效变体 common_au** 的真实段（deep_buffer :104-109、compressed_offload :110-124；逐字摘录，统一去除前导缩进）：
```xml
<mixPort name="deep_buffer" role="source"
        flags="AUDIO_OUTPUT_FLAG_DEEP_BUFFER">
    <profile name="" format="AUDIO_FORMAT_PCM_24_BIT_PACKED"
             samplingRates="44100,48000"
             channelMasks="AUDIO_CHANNEL_OUT_STEREO"/>
</mixPort>
```
（msmnile_au 目录变体的 deep_buffer 才是 PCM_16_BIT/48000（:102-106），但该变体装到 /vendor/etc/audio/、对 Framework 不生效，见 11.8.13；cuttlefish 文件本身 mixPort 仅 primary output/primary input 两个，见上。）

**Car端典型mixPort配置**（[`mixport_bus1_navigation_out`](device/generic/car/emulator/audio/audio_policy_configuration.xml:81)）：
```xml
<!-- Car端：每Bus一个mixPort，一一映射 -->
<mixPort name="mixport_bus0_media_out" role="source"
         flags="AUDIO_OUTPUT_FLAG_PRIMARY">
    <profile name="" format="AUDIO_FORMAT_PCM_16_BIT"
             samplingRates="48000" channelMasks="AUDIO_CHANNEL_OUT_STEREO"/>
</mixPort>
<mixPort name="mixport_bus1_navigation_out" role="source">
    <profile name="" format="AUDIO_FORMAT_PCM_16_BIT"
             samplingRates="48000" channelMasks="AUDIO_CHANNEL_OUT_STEREO"/>
</mixPort>
```

**Car端 vs Phone端差异**：
| 特征 | Phone端 | Car端 |
|------|---------|-------|
| mixPort数量 | 6-8个 | 每Bus一个 |
| flags使用 | 多种flags混合 | 仅PRIMARY给Bus0 |
| profile采样率 | 多采样率 | 固定48000 |
| 命名规则 | 功能命名(primary/deep_buffer) | Bus命名(mixport_busX_xxx) |

#### 11.8.7.3 输入flags详解

数值按 audio-hal-enums.h:461-470 修正：

| flags值 | 值(int) | 说明 |
|---------|---------|------|
| AUDIO_INPUT_FLAG_FAST | 0x01 | 低延迟输入 |
| AUDIO_INPUT_FLAG_HW_HOTWORD | 0x02 | 硬件热词检测 |
| AUDIO_INPUT_FLAG_RAW | 0x04 | 原始输入 |
| AUDIO_INPUT_FLAG_SYNC | 0x08 | 同步 |
| AUDIO_INPUT_FLAG_MMAP_NOIRQ | 0x10 | MMap低延迟输入 |
| AUDIO_INPUT_FLAG_VOIP_TX | 0x20 | VoIP发送专用 |
| AUDIO_INPUT_FLAG_HW_AV_SYNC | 0x40 | HW AV 同步 |
| AUDIO_INPUT_FLAG_DIRECT | 0x80 | 直接输入 |

**输入mixPort示例**（通用示意：空格分隔为 version=7.0 语法，1.0 下会静默失败；本树 emulator:126-130 实写为逗号分隔/PCM_16_BIT）：
```xml
<mixPort name="primary input" role="sink" maxActiveCount="0">
    <profile name="" format="AUDIO_FORMAT_PCM_8_24_BIT"
             samplingRates="8000 11025 12000 16000 22050 24000 32000 44100 48000"
             channelMasks="AUDIO_CHANNEL_IN_MONO AUDIO_CHANNEL_IN_STEREO
                           AUDIO_CHANNEL_IN_FRONT_BACK AUDIO_CHANNEL_INDEX_MASK_3"/>
</mixPort>
<mixPort name="hotword input" role="sink" flags="AUDIO_INPUT_FLAG_HW_HOTWORD">
    <profile name="" format="AUDIO_FORMAT_PCM_16_BIT"
             samplingRates="8000 11025 12000 16000 22050 24000 32000 44100 48000"
             channelMasks="AUDIO_CHANNEL_IN_MONO AUDIO_CHANNEL_IN_STEREO"/>
</mixPort>
```

**maxOpenCount/maxActiveCount**：
- maxActiveCount=0表示无限制（IOProfile.h:197-206 注释 "By convention 0 means no limit"）
- 通常用于限制并发录音数
- 两属性对输入/输出 mixPort 均解析（Serializer.cpp:491-498），不存在"输入端/输出端各用一个"的分工（maxOpenSessionsCount 为虚构属性）

#### 11.8.8.4 address属性详解

address属性用于区分同type的多个设备实例：

| 设备类型 | address格式 | 示例 |
|---------|------------|------|
| AUDIO_DEVICE_OUT_BUS | bus<编号>_<名称> | bus0_media_out |
| AUDIO_DEVICE_IN_BUS | input_bus_tone_zone_<X> | input_bus_tone_zone_0 |
| AUDIO_DEVICE_IN_FM_TUNER | tuner<N> | tuner0 |
| AUDIO_DEVICE_OUT_FM | fm_out | fm_out |
| 蓝牙A2DP | <mac_address> | 00:11:22:33:44:55 |
| USB | <card>-<device> | 1-0 |

```xml
<devicePort tagName="bus0_media_out" role="sink" type="AUDIO_DEVICE_OUT_BUS"
            address="bus0_media_out">
    <profile name="" format="AUDIO_FORMAT_PCM_16_BIT"
             samplingRates="48000" channelMasks="AUDIO_CHANNEL_OUT_STEREO"/>
    <gains>
        <gain name="" mode="AUDIO_GAIN_MODE_JOINT"
              minValueMB="-3200" maxValueMB="600"
              defaultValueMB="0" stepValueMB="100"/>
    </gains>
</devicePort>
```

#### 11.8.8.5 encodedFormats属性

仅蓝牙A2DP设备使用，声明支持的编码格式：

```xml
<devicePort tagName="BT A2DP Out" type="AUDIO_DEVICE_OUT_BLUETOOTH_A2DP" role="sink"
            encodedFormats="AUDIO_FORMAT_LDAC AUDIO_FORMAT_APTX AUDIO_FORMAT_APTX_HD
                           AUDIO_FORMAT_AAC AUDIO_FORMAT_SBC">
```

支持的encodedFormats值：

| 格式 | 说明 | 比特率 |
|------|------|--------|
| AUDIO_FORMAT_SBC | SBC基础编码 | 128-345 kbps |
| AUDIO_FORMAT_AAC | AAC编码 | 128-512 kbps |
| AUDIO_FORMAT_APTX | aptX编码 | 352 kbps |
| AUDIO_FORMAT_APTX_HD | aptX HD编码 | 576 kbps |
| AUDIO_FORMAT_LDAC | LDAC高解析 | 330/660/990 kbps |

### 11.8.9 gains 增益节点详解

gains定义设备的增益控制参数，Car端Bus设备必须有gains配置。

#### 11.8.9.1 gain属性表

| 属性 | 必填 | 类型 | 单位 | 说明 |
|------|------|------|------|------|
| channel_mask | 否 | string | — | AUDIO_GAIN_MODE_CHANNELS 模式下指定通道（Serializer.cpp:363-366；注：gain 元素**无 name 属性**，AudioGainTraits 不解析 name，:71-92） |
| mode | 是 | string | — | AUDIO_GAIN_MODE_JOINT等 |
| minValueMB | 是 | int | mB | 最小增益值 |
| maxValueMB | 是 | int | mB | 最大增益值 |
| defaultValueMB | 是 | int | mB | 默认增益值 |
| stepValueMB | 是 | int | mB | 增益步进值 |
| minRampMs | 否 | int | ms | 最小渐变时间 |
| maxRampMs | 否 | int | ms | 最大渐变时间 |
| useForVolume | 否 | bool | — | 是否用于音量控制 |

#### 11.8.9.2 mode取值

| mode | 值 | 说明 |
|------|-----|------|
| AUDIO_GAIN_MODE_JOINT | 0x01 | 联合模式，所有通道统一增益 |
| AUDIO_GAIN_MODE_CHANNELS | 0x02 | 独立通道模式，可单独设置 |
| AUDIO_GAIN_MODE_RAMP | 0x04 | 渐变模式，支持平滑过渡 |

Car端通常使用JOINT模式。

#### 11.8.9.3 gains数学约束

根据配置文件头部 "gain" 注释块（emulator :32-36、产品 common_au 头部同文）与 `CarAudioDeviceInfo.checkAudioGainConfiguration`（CarAudioDeviceInfo.java:207-216）的运行时校验：
```
maxValueMB >= minValueMB
defaultValueMB >= minValueMB && defaultValueMB <= maxValueMB
(maxValueMB - minValueMB) % stepValueMB == 0
(defaultValueMB - minValueMB) % stepValueMB == 0
```

**增益单位mB(millibel)**：
- 1 dB = 100 mB
- -3200 mB = -32 dB
- 600 mB = 6 dB
- 步进数 = (maxValueMB - minValueMB) / stepValueMB
- 示例：emulator (600-(-3200))/100 = 38步；产品 common_au (600-(-6000))/100 = 66步

#### 11.8.9.4 useForVolume属性

> **勘误（负结论）**："Car端Bus必须设true/只有useForVolume=true才被CarAudioService用于音量控制"无源码依据：12L `CarAudioDeviceInfo.getAudioGain` 只按 `MODE_JOINT` 选取增益、**不检查 useForVolume**（CarAudioDeviceInfo.java:193-200）；产品 common_au 的 Bus gains **全部未设置** useForVolume（:160-163 等），音量控制链路照常工作。useForVolume 仅为解析属性（默认 false，Serializer.cpp:403-404），供 AudioGain parcel/上层标记使用。

| 值 | 说明 | 使用场景 |
|----|------|---------|
| true | 标记该增益用于音量控制 | 可选标记（本产品未使用） |
| false(默认) | 默认 | 本产品 Bus gains 实际状态 |

#### 11.8.9.5 Phone端vs Car端gains对比

| 特征 | Phone端 | Car端 |
|------|---------|-------|
| 是否配置gains | 通常不配置 | Bus设备必须配置（否则抛异常） |
| useForVolume | 不设(默认false) | 本产品也不设（getAudioGain 按 JOINT 选取，与该属性无关） |
| 音量控制方式 | Stream Volume + 曲线插值 | Bus Gain直接控制 |
| minValueMB | N/A | 产品 -6000（emulator -3200） |
| maxValueMB | N/A | 600 |
| defaultValueMB | N/A | 0 |

#### 11.8.10.1 常用format值

### 11.8.11 route 路由详解

route定义mixPort与devicePort之间的连接关系。

| 属性 | 必填 | 类型 | 说明 |
|------|------|------|------|
| type | 是 | enum | 路由类型：mix或mux |
| sink | 是 | string | 目标端，devicePort的tagName或mixPort的name |
| sources | 是 | string | 源端列表，逗号分隔 |

#### 11.8.11.1 type取值

| type | 说明 | 使用场景 |
|------|------|---------|
| mix | 多源混合路由 | 绝大多数场景，允许多个source同时活跃 |
| mux | 多路复用路由 | 互斥路由，同一时刻仅一个source可用 |

**当前实现**：本树 12L 与产品配置中所有 route 均使用 type="mix"（mux 保留枚举未用）。

#### 11.8.11.2 输出路由规则

输出路由：mixPort(role=source) → devicePort(role=sink)

```xml
<!-- Phone端：多mixPort汇聚到同一设备（复合示意：cuttlefish Speaker route 实写仅 sources="primary output"） -->
<route type="mix" sink="Speaker"
       sources="primary output,raw,deep_buffer,compressed_offload,mmap_no_irq_out,voip_rx"/>
<route type="mix" sink="Wired Headset"
       sources="primary output,raw,deep_buffer,compressed_offload,mmap_no_irq_out,voip_rx"/>
```

```xml
<!-- Car端：一个mixPort到一个devicePort的一一映射 -->
<route type="mix" sink="bus0_media_out" sources="mixport_bus0_media_out"/>
<route type="mix" sink="bus1_navigation_out" sources="mixport_bus1_navigation_out"/>
```

#### 11.8.11.3 输入路由规则

输入路由：devicePort(role=source) → mixPort(role=sink)

```xml
<!-- Phone端：多输入设备汇聚到同一mixPort -->
<route type="mix" sink="primary input"
       sources="Built-In Mic,Built-In Back Mic,Wired Headset Mic,
                BT SCO Headset Mic,USB Device In,USB Headset In"/>
```

```xml
<!-- Car端：输入设备到输入mixPort -->
<route type="mix" sink="primary input"
       sources="Built-In Mic,Built-In Back Mic,Echo-Reference Mic"/>
<route type="mix" sink="mixport_tuner0" sources="FM Tuner"/>
<route type="mix" sink="mixport_input_bus_tone_zone_0" sources="Tone Generator 0"/>
```

#### 11.8.11.4 路由设计约束

| 约束 | 说明 |
|------|------|
| sink唯一性 | 同一sink可出现在多条route中，系统合并所有sources |
| source跨路由 | 同一source可出现在不同sink的route中 |
| 双向约束 | 输出route的sink必须是devicePort(role=sink) |
| 双向约束 | 输入route的sink必须是mixPort(role=sink) |
| Car端约束 | 每Bus的route建议1:1映射，避免多源混合 |

### 11.8.12 xi:include 外部引用

audio_policy_configuration.xml通过XInclude机制引用外部配置文件。

**本产品引用**（生效变体为 common_au——msmnile_gvmgh 产品把 common_au 安装为 `/vendor/etc/audio_policy_configuration.xml`（msmnile_au.mk:141），msmnile_au 目录自身的配置装到 `/vendor/etc/audio/`（:139，不在搜索路径内））：
common_au 的引用为**相对路径**（common_au/audio_policy_configuration.xml 末尾）：
```xml
<xi:include href="audio_policy_volumes.xml"/>
<xi:include href="default_volume_tables.xml"/>
```
（msmnile_au 目录变体才使用绝对路径 `/vendor/etc/...` 引用且含 usb/r_submix include（:361/:364/:371），但该变体不生效。）

**Car端引用**（a2dp/usb/r_submix include 在 [`:321/:324/:327`](device/generic/car/emulator/audio/audio_policy_configuration.xml:321)；:334 为 audio_policy_volumes include）：

```xml
<xi:include href="a2dp_audio_policy_configuration.xml"/>
<xi:include href="usb_audio_policy_configuration.xml"/>
<xi:include href="r_submix_audio_policy_configuration.xml"/>
```
