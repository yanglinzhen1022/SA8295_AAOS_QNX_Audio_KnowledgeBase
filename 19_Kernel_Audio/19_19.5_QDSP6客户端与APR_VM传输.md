# 19.5 QDSP6 客户端与 APR VM 传输：audio_q6.ko 与 audio_apr.ko

> [← 上一个](19_19.4_FE与Platform驱动.md) ｜ [本章导航](README.md) ｜ [下一个 →](19_19.6_用户态消费与插件分发.md)

本文是 19 章的技术核心：**Guest VM 内核里的 QDSP6 客户端层如何到达"ADSP"**。答案出乎很多资料意料——`apr_vm.c` 的传输层不是 rpmsg/glink，而是 **HAB**，与 QNX 侧 `gsl_be` 使用同一组 `MM_AUD_1/MM_AUD_2` 通道（[18.2](../18_AGM_GSL_Architecture/18_18.2_GSL跨VM控制与缓冲区.md) 已证 QNX 侧同通道）。

## 1. q6_dlkm（audio_q6.ko）：内核 QDSP6 客户端层

`CONFIG_SND_SOC_MSM_QDSP6V2_VM` 启用 **VM 变体**对象组（dsp/Kbuild:154-168），与非 VM 的 `QDSP6V2_INTF` 组（:134-151）几乎相同，唯一实质差异是共享内存分配器：

| 对象 | 作用（源文件可证） |
|---|---|
| `q6adm.o` | ADM（Audio Device Manager）客户端：路由/ copp |
| `q6afe.o` | AFE 客户端：端口/采样率/TDM 配置 |
| `q6asm.o` | ASM 客户端：压缩/PCM 会话 |
| `q6voice.o` / `q6lsm.o` | 语音 / 听觉检测 |
| `q6core.o` / `q6common.o` / `adsp_err.o` | 服务版本/公共/错误码 |
| `rtac.o` | 实时校准（RTAC）通道 |
| `audio_calibration.o` / `audio_cal_utils.o` | 校准数据库接口（与 [16.6/16.7 ACDB](../16_Vendor_QNX_Architecture/16_16.6_ACDB校准体系.md) 的双域关系另见勘误） |
| `msm_audio_ion_vm.o` | **VM 变体** ION 共享内存（非 VM 为 `msm_audio_ion.o`） |
| `q6_init.o` / `msm-audio-event-notify.o` | 装配与事件通知 |

`q6adm/q6afe/q6asm` 都是 `apr_register()`/`apr_send_pkt()` 的内核客户端（`EXPORT_SYMBOL`，ipc/apr_vm.c:928/:1055）。

## 2. apr_dlkm（audio_apr.ko）：APR over VM

`CONFIG_MSM_QDSP6_APRV2_VM` 的对象组是 **`apr_vm.o + apr_v2.o` 两个文件**（ipc/Kbuild:148-151；模块装配 :211-212）。注意与同文件另外两组的区别：

| CONFIG 组 | 对象 | 传输 |
|---|---|---|
| `APRV2_RPMSG` / `APRV3_RPMSG` | `apr.o + apr_v2.o/apr_v3.o + apr_tal_rpmsg.o` | rpmsg/glink（`apr_tal_rpmsg.c:56` `rpmsg_trysend`） |
| **`APRV2_VM`（本产品）** | **`apr_vm.o + apr_v2.o`（无 apr_tal；ipc/Kbuild:148-151）** | **HAB** |

`apr_vm.c` 的 probe（`apr_probe`，:1351）做三件事：

```c
// kernel/msm-5.4/techpack/audio/ipc/apr_vm.c:1364-1377（逐字摘录，统一左移）
	ret = habmm_socket_open(&hab_handle_tx,
			MM_AUD_1,
			0xFFFFFFFF,
			HABMM_SOCKET_OPEN_FLAGS_SINGLE_BE_SINGLE_FE);
	...
	ret = habmm_socket_open(&hab_handle_rx,
			MM_AUD_2,
			0xFFFFFFFF,
			HABMM_SOCKET_OPEN_FLAGS_SINGLE_BE_SINGLE_FE);
```

随后 `kthread_run(apr_vm_cb_thread, ...)` 创建接收线程（:1389-1391，线程内 `habmm_socket_recv` 循环 :595-600）。发送/接收均经 `habmm_socket_send/recv`（`apr_send_pkt` :821，EXPORT_SYMBOL :928），并维护 `hab_tx_lock`（:101）。

**这意味着**：

1. Guest VM 内核的 APR 包与 QNX 宿主的 `gsl_be`（[18.2](../18_AGM_GSL_Architecture/18_18.2_GSL跨VM控制与缓冲区.md)：`MM_AUD_1/MM_AUD_2` 打开 HAB 连接）**使用同一组 HAB 通道名**。两边谁先开、是否互通语义（HAB 通道是点对点 socket），树内无法静态证明"共享同一条连接"，但通道命名空间一致是明确事实。
2. `apr_tal_rpmsg.c` 在本产品内核配置下**不编译**——把"APR over rpmsg/glink"画进本产品内核路径是错的（那是非 VM 目标 `APRV2/V3_RPMSG` 的机制）。

## 3. 内核侧 APR 的服务模型（供内核客户端）

`apr_vm.c` 提供的注册/发送接口（`EXPORT_SYMBOL(apr_register)` :1055、`EXPORT_SYMBOL(apr_send_pkt)` :928）按 `dest/svc_name` 建服务路由，回调线程解析报文头后分发给注册回调（:574 "Rxed a packet for NULL callback" 为未注册服务时的日志）。调试面：`apr_debug_ops` file_operations（:85，debugfs）。这部分与经典 APR（[16.19 QNX apr_lib](../16_Vendor_QNX_Architecture/16_16.19_QNX_apr_lib_APR协议库.md) 兼容入口）语义同源，但**执行域不同**：内核 APR 的客户端是本节 q6_* 驱动，不是用户态。

## 4. 周边模块：adsp_loader / q6_notifier / SSR / snd_event

| 模块 | 源 | 职责（树内可证） |
|---|---|---|
| `audio_adsp_loader.ko` | `dsp/adsp-loader.c` | 用户态触发 ADSP PIL 加载的常规通道；**Guest VM 里 ADSP 由 QNX 侧管理**，本模块在本产品的实际行为未验证 |
| `audio_q6_notifier.ko` | q6_notifier_dlkm | ADSP up/down 状态通知给内核音频客户端 |
| SSR | `CONFIG_MSM_QDSP6_SSR` | ADSP 重启订阅框架 |
| `audio_snd_event.ko` | `soc/snd_event.c` | 声卡级事件（如耳机/USB 插拔联动）注册分发框架 |

## 5. 勘误与边界

> **勘误（概念纠偏：QNX 侧 GPR ≠ 本节内核 APR）**：QNX 宿主内部使用 GPR over GLink（[16.19](../16_Vendor_QNX_Architecture/16_16.19_QNX_apr_lib_APR协议库.md) 兼容入口与 18.3 的 GPR 命令组），而 **Android Guest VM 内核**的 APR 走 HAB。三个名字（内核 APR-VM、用户态 GSL 前端、QNX 侧 GPR）是三个执行域的三种通道选择，不能合并画成"APR→GPR→DSP 一条线"。
>
> **边界（habmm 内核驱动不在 techpack）**：`apr_vm.c:32` `#include <linux/habmm.h>`；HAB 驱动（habmm 设备）由 hypervisor 侧提供，不在 `techpack/audio/` 内，本库不展开其实现。HAB 语义（export/import、MM_AUD 通道族）在 [18.2](../18_AGM_GSL_Architecture/18_18.2_GSL跨VM控制与缓冲区.md) 从 gsl_be 侧已讲解，此处不重复。
>
> **边界（RTAC/校准与 QNX ACDB 的关系）**：内核 `audio_calibration/rtac` 面向内核 Q6 客户端的校准；产品 ACDB 数据库加载主线在 QNX 侧（[16.6](../16_Vendor_QNX_Architecture/16_16.6_ACDB校准体系.md)、[16.7](../16_Vendor_QNX_Architecture/16_16.7_ACDB校准数据Android与QNX双域共享.md)）。两者是否在本产品并存、谁写 ADDB，未做运行时验证。
