# 19.4 FE 与 Platform 驱动：audio_platform.ko 与 audio_native.ko

> [← 上一个](19_19.3_ASoC声卡注册.md) ｜ [本章导航](README.md) ｜ [下一个 →](19_19.5_QDSP6客户端与APR_VM传输.md)）

`audio_platform.ko`（`platform_dlkm.o`，`CONFIG_SND_SOC_QDSP6V2`）承载 FE PCM/compress 设备、Q6 DAI、路由与后处理配置；`audio_native.ko`（`native_dlkm.o`，`CONFIG_MSM_QDSP6V2_CODECS`）承载 native 编解码桩。本文按对象组讲解它们各自注册什么、服务谁。

## 1. platform_dlkm 的对象组（asoc/Kbuild:204-245）

| 对象（.o） | 职责（从文件与初始化函数可证） |
|---|---|
| `msm-pcm-q6-v2` | FE PCM 播放/录音设备（MultiMedia* 前端） |
| `msm-pcm-q6-noirq` | no-irq（mmap 轮询型）PCM |
| `msm-compress-q6-v2` | compress 设备（offload 通路） |
| `msm-pcm-routing-v2` / `msm-pcm-routing-auto` | FE↔BE 路由 mixer；**本产品选 routing-auto**（asoc/Kbuild:218-224：`ifeq (y,$(findstring y,$(CONFIG_QTI_QUIN_GVM) $(CONFIG_PLATFORM_AUTO)))` 命中 QUIN_GVM 分支，该分支**不编译** `msm-pcm-voice-v2`/`msm-pcm-voip-v2`） |
| `msm-pcm-afe-v2` / `msm-pcm-dtmf-v2` / `msm-pcm-hostless` / `msm-pcm-host-voice-v2` / `msm-pcm-loopback-v2` / `msm-pcm-voice-v2` / `msm-pcm-voip-v2` / `msm-transcode-loopback-q6-v2` | 专用前端：AFE 直通、DTMF、hostless、通话、回环、转码（voice/voip 对象在 QUIN_GVM 分支不编译，见上行） |
| `msm-dai-fe` / `msm-dai-q6-v2` / `msm-dai-q6-hdmi-v2` / `msm-dai-stub-v2` | FE DAI / Q6 BE DAI / HDMI DAI / stub DAI |
| `msm-lsm-client` | 听觉场景检测（LSM）前端 |
| `msm-audio-effects-q6-v2` / `msm-qti-pp-config` / `msm-ds2-dap-config` | 音效/后处理内核侧配置通道（注：`msm-ds2-dap-config` 受 `CONFIG_DOLBY_DS2`/`CONFIG_DOLBY_LICENSE` 门控，asoc/Kbuild:235-240；本产品 gvmauto.conf 未启用这两个开关，[19.2 §4](19_19.2_构建配置与模块清单.md)，不编入 audio_platform.ko） |
| `platform_init(_auto)` | 上述驱动的注册编排 |

`platform_init_auto.c`（本产品 auto 变体入口）注册顺序（`platform_init_auto.c:11-31`，逐字摘录，统一左移缩进）：

```c
// kernel/msm-5.4/techpack/audio/asoc/platform_init_auto.c:11-31（逐字摘录，统一左移）
static int __init audio_platform_init(void)
{
	msm_compress_dsp_init();
	msm_fe_dai_init();
	msm_dai_q6_hdmi_init();
	msm_dai_q6_init();
	msm_dai_slim_init();
	msm_dai_stub_init();
	msm_lsm_client_init();
	msm_pcm_afe_init();
	msm_pcm_dtmf_init();
	msm_pcm_hostless_init();
	msm_voice_host_init();
	msm_pcm_loopback_init();
	msm_pcm_noirq_init();
	msm_pcm_dsp_init();
	msm_soc_routing_platform_init();
	msm_transcode_loopback_init();

	return 0;
}
```

> 对象组与 `platform_init_auto.c` 的对应：Kbuild 把 `platform_init_auto.o` 编进 `platform_dlkm`（asoc/Kbuild:226-230，同一 findstring 条件），函数名与对象一一对应（如 `msm_pcm_dsp_init` → `msm-pcm-q6-v2`，`msm_fe_dai_init` → `msm-dai-fe`）。**auto 变体与普通 `platform_init.c` 的函数集差异**：auto 版**不含** `msm_pcm_voice_init()`/`msm_pcm_voip_init()`（与 Kbuild 同分支不编译 voice/voip 对象一致）；slim/stub 等 DAI 初始化两版均有。

## 2. FE PCM 设备的内核侧语义

`msm-pcm-q6-v2` 这类 FE 驱动在 `pcm_open` 时创建内核 `snd_pcm_runtime`，其 `hw_params`/`prepare`/`start` 经 platform 驱动转入 QDSP6 客户端层（`q6asm`/`q6adm`/`q6afe`，见 [19.5](19_19.5_QDSP6客户端与APR_VM传输.md)），buffer 由 `msm_audio_ion`（VM 变体 `msm_audio_ion_vm.o`）映射给远端。**树内证据到此为止的具体分工**：

- 用户态 tinyalsa `hw_ops` 路径（type=HW，见 [19.6](19_19.6_用户态消费与插件分发.md)）打开的就是这些 FE 设备；
- 用户态 AGM 插件路径（type=PLUGIN）**绕过**这些 FE 驱动，在用户态完成会话/图管理后经 HAB 出域；
- 两条路径是否并存、按 card/device 如何分流，由启动分支与卡定义决定（Elite 分支走 HW、AudioReach 分支全 PLUGIN，见 [19.6 §3](19_19.6_用户态消费与插件分发.md)）。

## 3. audio_native.ko：native 编解码桩（native_dlkm）

`dsp/codecs/Kbuild:89-116` 的 `NATIVE_OBJS`（ifdef :89，对象列表 :90-115）：`q6audio_v2.o`、`q6audio_v2_aio.o`、`audio_utils_aio.o`、`audio_utils.o`、`audio_native.o`、`aac_in.o`、`amrnb_in.o`、`amrwb_in.o`、`audio_aac.o`、`audio_alac.o`、`audio_amrnb.o`、`audio_amrwb.o` 等。这一组是 **native（内核直通 DSP）编解码会话**的 AIO 框架与各格式的桩——服务于内核侧 PCM/compress 之外的 native 流（历史上用于语音/voip/特定压缩格式）。

> **范围声明**：本节只确认"这组对象存在且属于 audio_native.ko"。哪些产品场景实际使用 native 通路（如 InCallMusic、voip）**未在树内逐一追踪**，不在此展开；通话路径的 Framework/HAL 侧见 [3.8 AudioMode](../03_Java_Framework_Layer/03_3.8_AudioMode状态机与通信设备路由.md) 与 [11.7 OEM 定制](../11_Vendor_Layer/11_11.7_OEM定制指南.md)。
