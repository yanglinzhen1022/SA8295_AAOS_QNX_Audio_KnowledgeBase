# AudioReach 音频知识库分层重构设计

## 1. 文档用途与当前阶段

本文是知识库维护设计，不是面向读者的音频课程，不加入主阅读目录。

用户已确认重构方向；本文将确认内容落为书面设计，供审阅。本文不表示正文已完成源码核验，也不表示已授权批量改写。书面设计确认后，再制定首批实施计划。

## 2. 用户目标与约束

目标：在现有 `SA8295_AAOS_QNX_Audio_KnowledgeBase` 中建设专业、全面、便于系统学习的音频知识库。

已确认的要求：

1. 主线为本地 Android 12L / API 32、SA8295、QNX，实际使用 AudioReach；只研究 AudioReach，不展开 Elite。
2. 先读相关源码，再形成知识讲解。不得凭经验补造类、接口、配置、调用关系、机制或性能数字。
3. 保持分层学习结构，由浅入深；源码是知识的来源，不把知识库写成代码目录或工程审计报告。
4. 保留并加强必要的源码调用流程图、时序图、状态图、关键源码片段及解释。
5. 保留旧文档中有价值的内容，但必须重新核对；不是简单替换版本名或只修排版。
6. Android 14 及更新版本作为独立、有可靠出处的补充，不混入本地实现主线。
7. 暂不建设基线管理、证据台账、编译打包教程或审计系统；不另建平行知识库。
8. 目录与内容优化细节由维护者负责，不要求用户逐篇决定。

维护边界：本地产品源码只读；修改限于知识库。实际运行方式以用户确认为范围前提，但具体接口行为仍须读实现，不将范围确认等同于已做实机测试。

## 3. 成品定位

成品是“分层教材 + 源码解析 + 跨层专题 + 调试参考”。

一篇文章应让读者理解：这个模块为什么存在、承担什么职责、怎样工作、如何与上下层配合，以及出现问题时应该观察什么。

专业性以解释准确、边界清晰和问题覆盖为准；全面性以重要机制、场景与异常路径的覆盖为准，不以篇数、行数、图数或源码粘贴量作为目标。

范围不包含：Elite 专题、缺失实现的内部算法猜测、板卡原理图未提供时的实际接线推测、没有测试记录的性能结论、全量系统编译或实机操作。

## 5. 文章写法

### 5.1 通用结构

按内容需要采用以下结构，不强制每篇凑齐相同数量的小节：

1. 学习目标与前置知识。
2. 这个模块解决什么问题，边界是什么。
3. 核心概念与对象关系。
4. 正常工作流程与上下层接口。
5. 关键实现片段及逐段解释。
6. 缓冲、线程、同步、状态变化等深入机制。
7. 典型场景、失败与恢复行为。
8. 容易混淆的概念、观察方法与小结。
9. 精简的相关源码位置及延伸阅读。

基础文章重概念，核心实现文章重机制，专题重协作。不要把函数列表替代解释，也不要用“深度解析”标题掩盖没有实现依据的概述。

### 5.2 源码片段规则

- 精确摘录标明文件与函数；删除中间代码时显式标注省略。
- 为解释添加的中文注释与原注释区分。
- 简化代码明确标记为“按本地实现整理的伪代码”，保持判断条件、调用顺序、返回及错误语义，不伪装为逐字源码。
- 代码后解释输入、状态变化、关键分支、输出及设计作用。
- 不使用旧文章的行号替代本次定位；不粘贴大段与讲解无关的源码。
- 源码位置使用可配置根目录概念或普通路径说明；不继续制造无法解析的 `Foo.cpp:123` Markdown 相对链接。尚无源码浏览器时，路径和符号以代码格式呈现。

### 5.3 图示规则

必要的图示是正文的一部分，不能为精简而删除关键调用图。

| 图类型 | 使用场景 | 必须表达的边界 |
|---|---|---|
| 分层/职责图 | 建立系统与模块全貌 | 执行域、职责、控制和数据连接的区别 |
| 源码调用流程图 | 分支、路由选择、参数处理、错误处理 | 实际入口、条件、调用关系、退出路径 |
| 时序图 | IPC、异步回调、启动/停止及跨模块协作 | 进程/线程、同步与异步、回复与回调 |
| 状态图 | Track、Stream、焦点、设备等状态变化 | 真实状态、触发条件、异常与恢复 |
| 缓冲/数据流图 | PCM、共享内存、FMQ、跨 VM 数据 | 所有权、读写方、复制与映射的已知边界 |
| 类关系图 | 继承、组合、工厂与管理关系 | 区分对象关系与实际函数调用 |

图中使用真实符号或明确的概念标签。概念步骤不伪装成函数名；调用图不得添加不存在的中间接口；多条条件路径不能拼成一条“全栈路径”。

大图拆成总览和局部图。每张关键图有文字解释，关键代码与图中步骤对应。Mermaid 语法通过不等于技术内容正确。

## 6. 源码驱动的研究方法

这是维护者工作方式，不建设成读者需要学习的证据章节。

1. 先定位实际接口和实现，再阅读调用方、被调用方、数据结构与影响本问题的条件。
2. 遇到函数指针、Binder/HIDL、插件或跨 VM 边界，追到接收/分发实现；无法继续时说明可见边界。
3. 研究实现的同时检查旧文章，判定保留、修正、合并、移出主线或删除，不从旧叙述反推源码。
4. 记录必要的研究进度与未解问题于维护材料，不把这些台账塞入正文。
5. 编译与启动配置仅用于确认行为适用条件，不把编译系统做成课程内容。
6. 不自动运行完整构建、刷机、启动服务或硬件控制命令。静态分析与实机验证在描述中明确区分。
7. 模块只有头文件/预编译库时，只解释可确认的接口、协议及调用关系，不推断内部算法和性能。
8. 未确认结论不进入确定性正文；确有教学必要时，简短说明本地可见范围或验证限制。

Android 14+ 以固定 AOSP 版本源码或官方资料为来源。旧文档中的新版内容同样重新核对，不直接搬迁后标为可信。当前优先完成本地主线，不以新版本拓展阻塞主线重构。

## 7. 全面性的覆盖维度

覆盖维度是后续分批研究的范围，不表示所有能力都在当前产品启用。

- 播放与录音：创建、启动、数据交换、暂停/停止、释放、共享内存、时间戳与恢复。
- 执行路径：普通混音、Fast、Direct、Offload、AAudio/MMAP 的本地选择机制与约束。
- 策略与控制：usage/context、焦点、音量、mute/duck、设备热插拔、路由与 Patch。
- 车载：多音区、用户/乘员关系、Bus、音量组、外部音频与 AudioControl。
- 音效与语音：软件/DSP 音效、录音预处理、AEC 参考、通话、SoundTrigger；支持程度以本地实现为准。
- 外设与协议：蓝牙不同角色与路径、USB/HDMI、有线与车载音频总线；不臆测板级连接。
- 平台：PAL、AGM/GSL、内核/QNX、DSP 接口、校准参数及配置之间的关系。
- 非正常路径：underrun/overrun、失败返回、断连、服务死亡、SSR、资源回收、并发与恢复。
- 调试：问题现象、观察入口、判断依据、结论边界及下一步定位。

没有源码依据的能力不为凑齐清单而写成当前产品功能。

## 9. 验收标准

### 技术准确性

- 本批新增或改写的关键机制、调用图与代码片段均已对照对应实现。
- 路径中区分 Android/QNX/DSP、控制/数据、同步/异步及条件分支。
- 不混用 Elite、其他平台或 Android 14+ 的实现补写本地主线。
- 旧文档中的错误表格、图示和正文同步修正，而非只追加更正声明。
- 对源码可见边界、功能条件和未经实测的现象采用准确措辞。

### 教学质量

- 先建立概念，再用图示与代码解释机制。
- 关键流程有必要的图；关键分支有对应解释，不堆图、不只贴代码。
- 同一概念有主要解释位置；阅读顺序、前置知识和回链清楚。
- 失败路径与易错点服务于理解，不堆积无关 API 或枚举。

### 文档质量

- 修改涉及的 Markdown 跳转目标与标题锚点有效。
- 图示、表格、代码围栏格式正确；Mermaid 实际渲染未执行时不宣称渲染通过。
- 源码路径、函数与摘录能在本地重新定位；伪代码标注清楚。
- 不以自动链接检查代替技术复核，也不以主观“全面”代替已完成范围说明。
