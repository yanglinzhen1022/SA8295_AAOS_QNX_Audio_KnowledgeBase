## 2.10 ExoPlayer调用路径 — 应用层音频播放引擎

### 2.10.1 模块职责与源码位置

ExoPlayer是Google开源的媒体播放器库（非AOSP原生框架API，但在Android生态广泛使用），提供比MediaPlayer更灵活的播放能力。核心音频特性：

- **直接AudioTrack**：绕过MediaPlayer/MediaPlayerService，应用进程内直接创建AudioTrack
- **自适应码率**：DASH/HLS/SmoothStreaming自适应流切换
- **2种输出路径**（2.11.4）：PCM解码→AudioTrack / Passthrough直传（Offload为新版特性）
- **AudioProcessor链**：SilenceSkipping + Sonic(变速) + 自定义处理
- **隧道模式**：音视频同步由AudioFlinger/HW Composer负责

**源码位置**（本树 `external/exoplayer/`，版本 **2.11.4**，见 `library/common/src/main/java/com/google/android/exoplayer2/ExoPlayerLibraryInfo.java:32` `VERSION = "2.11.4"`）：

| 模块 | 文件 | 职责 |
|------|------|------|
| AudioSink接口 | [`AudioSink.java`](external/exoplayer/tree/library/core/src/main/java/com/google/android/exoplayer2/audio/AudioSink.java) | 音频输出抽象层 |
| DefaultAudioSink | [`DefaultAudioSink.java`](external/exoplayer/tree/library/core/src/main/java/com/google/android/exoplayer2/audio/DefaultAudioSink.java) | AudioTrack创建+写入+位置追踪 |

### 2.10.3 输出模式详解（2.11.4：PCM与Passthrough两种）

2.11.4 的 `DefaultAudioSink` 按 `Configuration.isInputPcm`（[`Configuration`](external/exoplayer/tree/library/core/src/main/java/com/google/android/exoplayer2/audio/DefaultAudioSink.java:1433)）区分两条路径：

| 输出路径 | 判定 | AudioTrack编码 | AudioProcessor链 | 适用格式 |
|----------|-------|---------------|-----------------|---------|
| PCM路径 | `isInputPcm=true` | ENCODING_PCM_16BIT / ENCODING_PCM_FLOAT | 全链路(Sonic+Silence+自定义) | 所有解码后PCM |
| Passthrough路径 | `isInputPcm=false` | 原始压缩编码格式 | **不可用** | 设备支持的压缩格式直传 |

（新版 ExoPlayer 的 `OUTPUT_MODE_PCM/OFFLOAD/PASSTHROUGH` 三常量与 Offload 模式不属于本树 2.11.4。）

**PCM模式详细流程**：

```
编码数据 → MediaCodec解码 → PCM(16bit/float)
→ ResamplingAudioProcessor(重采样到目标格式)
→ ChannelMappingAudioProcessor(通道映射)
→ TrimmingAudioProcessor(裁剪encoder delay/padding)
→ 用户自定义AudioProcessor[]
→ SilenceSkippingAudioProcessor(静音跳过)
→ SonicAudioProcessor(变速变调)
→ AudioTrack.write()
```

> Offload（压缩码流直传DSP、50秒缓冲、gapless、DSP随时回收等）是 ExoPlayer 2.17+ 特性，本树源码不含；车载主线若需 Offload，走 NuPlayer/AudioTrack offload 路径而非 ExoPlayer。

### 2.10.5 AudioTrack创建流程

DefaultAudioSink在`configure()`+`initializeAudioTrack()`中创建AudioTrack：

```mermaid
sequenceDiagram
    participant AR as MediaCodecAudioRenderer
    participant DAS as DefaultAudioSink
    participant CFG as Configuration
    participant APT as AudioProcessorChain
    participant AT as AudioTrack

    AR->>DAS: configure(encoding, channelCount, sampleRate, ...)
    DAS->>DAS: 判定 isInputPcm（PCM路径或Passthrough路径）
    DAS->>CFG: 创建pendingConfiguration
    Note over DAS: PCM路径: 选择toIntPcm/toFloatPcm processors
    Note over DAS: Passthrough路径: 无AudioProcessor
    DAS->>DAS: 计算bufferSize
    DAS->>APT: configure(audioProcessors, sampleRate, channelCount, encoding)
    APT-->>DAS: 处理链配置完成
    DAS->>DAS: 切换pendingConfiguration → configuration

    AR->>DAS: handleBuffer(buffer, presentationTimeUs, encodedAccessUnitCount)
    DAS->>DAS: 首次handleBuffer时初始化AudioTrack
    DAS->>AT: new AudioTrack(streamType, sampleRate, channelConfig, encoding, bufferSize, mode)
    Note over AT: PCM: MODE_STREAM + ENCODING_PCM_16BIT/FLOAT
    Note over AT: Passthrough: MODE_STREAM + 原始压缩编码
    DAS->>AT: play() (延迟启动，等首帧写入)
    AT-->>DAS: audioSessionId
```

**bufferSize计算策略**（2.11.4，`DefaultAudioSink.java:1569-1575`）：

1. PCM路径：`max(getMinBufferSize(), durationUs→bytes) × BUFFER_MULTIPLICATION_FACTOR`
2. Passthrough路径：`PASSTHROUGH_BUFFER_DURATION_US→bytes × AC3因子(如需要)`

```java
// 最简构造
```

**解码→输出完整流程**：

```mermaid
sequenceDiagram
    participant EP as ExoPlayer
    participant AR as MediaCodecAudioRenderer

    participant AS as DefaultAudioSink
    participant AT as AudioTrack

    EP->>AR: render(positionUs, elapsedRealtimeUs)
    AR->>AR: processOutputBuffer()
```

**onOutputMediaFormatChanged**（[`onOutputMediaFormatChanged`](external/exoplayer/tree/library/core/src/main/java/com/google/android/exoplayer2/audio/MediaCodecAudioRenderer.java:397)，2.11.4 方法名是 onOutputMediaFormatChanged）：

- Passthrough时用 `passthroughMediaFormat`（MIME改为原始压缩格式）并通过 `getPassthroughEncoding()` 取编码；否则用解码器输出 MediaFormat
- 处理 Vivo 设备 workaround（`VIVO_BITS_PER_SAMPLE_KEY`）取 PCM 位深；否则 `getPcmEncoding(inputFormat)`
- 从 MediaFormat 提取 channelCount/sampleRate
- `codecNeedsDiscardChannelsWorkaround && channelCount==6 && input<6ch` 时生成丢弃声道的 channelMap
- 调用 `audioSink.configure(encoding, channelCount, sampleRate, ...)`

### 2.10.7 AudioProcessor链详解

[`DefaultAudioProcessorChain`](external/exoplayer/tree/library/core/src/main/java/com/google/android/exoplayer2/audio/DefaultAudioSink.java:126)处理链结构：

```
输入PCM → [用户自定义AudioProcessor...] → SilenceSkippingAudioProcessor → SonicAudioProcessor → 输出PCM
```

**toIntPcmAvailableAudioProcessors**（PCM→16bit路径）：

| 处理器 | 功能 | 默认激活条件 |
|-------|------|------------|
| `ResamplingAudioProcessor` | 重采样到16-bit PCM | 非16-bit输入时 |
| `ChannelMappingAudioProcessor` | 通道重映射 | outputChannels指定时 |
| `TrimmingAudioProcessor` | 裁剪encoder delay/padding | 有encoderDelay/Padding时 |
| `[用户自定义...]` | 自定义处理 | 用户配置 |
| `SilenceSkippingAudioProcessor` | 静音跳过 | skipSilence=true |
| `SonicAudioProcessor` | 变速变调 | speed≠1.0或pitch≠1.0 |

**toFloatPcmAvailableAudioProcessors**（PCM→float路径）：

| 处理器 | 功能 |
|-------|------|
| `FloatResamplingAudioProcessor` | 16-bit PCM→32-bit float |

> **关键设计**：Float输出模式不支持AudioProcessor链（除FloatResampling外），因为变速/变调/静音跳过需要整数PCM处理。

### 2.10.9 AudioTrack位置追踪

[`AudioTrackPositionTracker`](external/exoplayer/tree/library/core/src/main/java/com/google/android/exoplayer2/audio/AudioTrackPositionTracker.java)负责AudioTrack播放位置的精确追踪和平滑处理：

**位置获取策略**：

| API级别 | 位置获取方式 | 精度 |
|---------|------------|------|
| API 19+ | `AudioTrack.getTimestamp()` | 高精度(硬件timestamp) |
| 所有级别 | `AudioTrack.getPlaybackHeadPosition()` | 中精度(可能不连续) |
| 辅助 | 计算writtenFrames - playbackHeadPosition | 缓冲区剩余推算 |

**位置平滑算法**：

1. 定期调用`AudioTrack.getTimestamp()`获取硬件时间戳
2. 检测spurious timestamp（位置回跳超过阈值→InvalidAudioTrackTimestampException）
3. 线性插值平滑position，避免AudioTrack.getPlaybackHeadPosition()的16-bit截断不连续
4. 结合mediaPositionParametersCheckpoints队列，处理变速变调下的媒体时间映射

### 2.10.10 Passthrough模式详解

Passthrough模式将压缩音频（如AC3/EAC3/DTS）直接传给AudioTrack，不做解码：

**Passthrough判定**（`MediaCodecAudioRenderer.java:303-309`）：

```java
passthroughEnabled =
    MimeTypes.AUDIO_RAW.equals(codecInfo.mimeType)
        && !MimeTypes.AUDIO_RAW.equals(format.sampleMimeType);
MediaFormat mediaFormat =
    getMediaFormat(format, codecInfo.codecMimeType, codecMaxInputSize, codecOperatingRate);
codec.configure(mediaFormat, /* surface= */ null, crypto, /* flags= */ 0);
if (passthroughEnabled) {
    // Store the input MIME type if we're using the passthrough codec.
    passthroughMediaFormat = mediaFormat;
    passthroughMediaFormat.setString(MediaFormat.KEY_MIME, format.sampleMimeType);
} else {
    passthroughMediaFormat = null;
}
```
> 源码：`MediaCodecAudioRenderer.java:303-313`（逐字摘录，2.11.4）：Passthrough 即用 RAW 编解码器占位、把 MIME 改回原始压缩格式。

**AudioCapabilities作用**：

- 查询设备是否支持特定编码的Passthrough
- 默认能力 = 不支持任何Passthrough
- 通过`AudioCapabilities.getAudioCapabilities(context)`获取设备真实能力
- HDMI/S/PDIF连接时通常支持AC3/DTS Passthrough

**Passthrough vs Offload区别**（Offload 仅存在于新版 ExoPlayer/AudioTrack，本树 ExoPlayer 无此模式）：

| 维度 | Passthrough（2.11.4支持） | Offload（新版，非本树） |
|------|-------------|---------|
| 数据流向 | AudioTrack→AudioFlinger→HAL→DSP | AudioTrack→AudioFlinger→HAL→DSP |
| AudioTrack编码 | 压缩编码(ENCODING_AC3等) | 压缩编码(setOffloadMode) |
| 解码位置 | 外部接收器/AVR | DSP |
| 缓冲时长 | 250ms | 50秒 |
| 变速变调 | 不支持 | 不支持 |

### 2.10.11 隧道模式(Tunneling)

隧道模式将音视频同步交给底层硬件，ExoPlayer不做时钟驱动：

**启用条件**：

- API 21+（`enableTunnelingV21()`）
- `MediaCodecAudioRenderer.onEnabled()`中根据getConfiguration().tunneling决定
- AudioTrack创建时设置`FLAG_TUNNEL_MODE`
- AudioTrack的sessionId与视频MediaCodec共享

**隧道模式约束**：

- AudioProcessor不能改变输出帧时长（变速不可用）
- BufferProcessor必须立即输出最后一帧输入后的输出
- ExoPlayer不驱动MediaClock，由AudioFlinger/HW Composer同步

### 2.10.15 Offload缓冲与事件回调

| `onOffloadBufferEmptying()` | DSP缓冲正在清空 |
| `onOffloadBufferFull()` | DSP缓冲已满 |

**Offload恢复策略**：

- `ERROR_DEAD_OBJECT` → 重建AudioTrack并重试
- `AUDIO_TRACK_RETRY_DURATION_MS`(100ms)内的重试不抛异常
- `PendingExceptionHolder`延迟异常上报机制

### 2.10.16 格式支持判断流程（2.11.4）

[`MediaCodecAudioRenderer.supportsFormat()`](external/exoplayer/tree/library/core/src/main/java/com/google/android/exoplayer2/audio/MediaCodecAudioRenderer.java:211)的判断逻辑（解码器侧，AudioSink 能力用 `audioSink.supportsOutput()`）：

```mermaid
graph TD
    A["Format输入"] --> B{"是音频MIME?"}
    B -->|"否"| F["FORMAT_UNSUPPORTED_TYPE"]
    B -->|"是"| G{"usePassthrough<br>(RAW占位+外部支持)?"}
    G -->|"是"| D["FORMAT_HANDLED<br>ADAPTIVE_NOT_SEAMLESS"]
    G -->|"否"| H{"audioSink.supportsOutput<br>(channelCount, PCM编码)?"}
    H -->|"RAW且不支持/非RAW且16bit不支持"| F2["FORMAT_UNSUPPORTED_SUBTYPE"]
    H -->|"支持"| I{"解码器列表非空?"}
    I -->|"空"| F2
    I -->|"非空"| J{"DRM支持?"}
    J -->|"否"| F3["FORMAT_UNSUPPORTED_DRM"]
    J -->|"是"| K["isFormatSupported→<br>FORMAT_HANDLED/FORMAT_EXCEEDS_CAPABILITIES"]
```

**与新版差异**：新版把 AudioSink 侧抽成 `supportsFormat(Format)/getFormatSupport(Format)` 三态（SUPPORTED_DIRECTLY/WITH_TRANSCODING/UNSUPPORTED）；2.11.4 只有 `supportsOutput(channelCount, encoding)` 布尔判定，解码器侧 `supportsFormat`（[:211](external/exoplayer/tree/library/core/src/main/java/com/google/android/exoplayer2/audio/MediaCodecAudioRenderer.java:211)）负责整体仲裁。

### 2.10.17 keepSessionIdAudioTrack（2.11.4 的 seek 保留机制）

网上文档的 `experimentalSetEnableKeepAudioTrackOnSeek()/experimentalFlushWithoutAudioTrackRelease()` 是新版 API。2.11.4 的对应机制是 **keepSessionIdAudioTrack**（[`keepSessionIdAudioTrack`](external/exoplayer/tree/library/core/src/main/java/com/google/android/exoplayer2/audio/DefaultAudioSink.java:270)）：

- flush 重建 AudioTrack 时，若 sessionId 变化，先用一个两字节缓冲的最小 AudioTrack（`initializeKeepSessionIdAudioTrack`，:1171）占住旧 sessionId，避免依赖该 session 的 AudioEffect 被重置
- 真正的 AudioTrack 重建后，`keepSessionIdAudioTrack` 异步释放（:1052）

**seek处理对比**：

| 操作 | 2.11.4 行为 |
|------|-----------|
| seek时 | audioSink.flush() → 若sessionId变→占位保session → 重建AudioTrack |
| 延迟 | 重建开销存在，但 session 相关效果器状态得到保留 |

### 2.10.18 ExoPlayer vs MediaPlayer音频路径对比

| 维度 | ExoPlayer | MediaPlayer |
|------|----------|------------|
| AudioTrack创建位置 | 应用进程(DefaultAudioSink) | mediaserver进程(MediaPlayerService) |
| 解码器 | 应用进程(MediaCodec) | mediaserver进程(AwesomePlayer/NuPlayer) |
| IPC开销 | 无(同一进程) | Binder IPC每帧数据 |
| AudioProcessor | 支持(Sonic/SilenceSkip/自定义) | 不支持 |
| 变速变调 | SonicAudioProcessor(高质量) | PlaybackParams(低延迟/不可靠) |
| Passthrough | 支持(需AudioCapabilities) | NuPlayer自动判断 |
| Offload | 支持(需配置) | NuPlayer自动判断 |
| 隧道模式 | 支持(V21+) | NuPlayer支持 |
| 自适应码率 | DASH/HLS/SmoothStreaming | 不支持 |
| 位置追踪 | AudioTrackPositionTracker(平滑) | MediaPlayer.getTimestamp |
| 错误恢复 | PendingExceptionHolder+重试 | 有限恢复 |
| 适用场景 | 流媒体/自定义处理/低延迟 | 简单本地播放 |

### 2.10.19 AAOS车载场景中的ExoPlayer

在AAOS车载系统中，ExoPlayer的优势：

- **多音区路由**：通过`setAudioAttributes()` + CarAudioManager设置音区路由
- **低延迟播放**：避免mediaserver IPC开销
- **省电**：Passthrough直传减少解码CPU负载（Offload省电需新版 ExoPlayer，本树无）
- **静音跳过**：导航播报自动跳过静音段
- **隧道模式**：与车载视频显示硬件同步
- **自适应码率**：车载网络不稳定时自动降级
