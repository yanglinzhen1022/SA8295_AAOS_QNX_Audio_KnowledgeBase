## 14.3 LE Audio — 低功耗蓝牙音频（12L：早期未完成实现；完整栈为 Android 13+）

> **版本边界（更正）**：12L 本树**已有早期 LE Audio 实现**——经典蓝牙应用 [`packages/apps/Bluetooth`](packages/apps/Bluetooth/src/com/android/bluetooth/le_audio/LeAudioService.java) 内含 `LeAudioService.java`（844 行）/`LeAudioStateMachine.java`（571 行）/`LeAudioNativeInterface.java`（217 行）/`LeAudioStackEvent.java`（168 行），framework 侧有公共 API [`BluetoothLeAudio`](frameworks/base/core/java/android/bluetooth/BluetoothLeAudio.java) 与设备常量 [`DEVICE_OUT_BLE_HEADSET/0x20000000、DEVICE_OUT_BLE_SPEAKER/0x20000001`](frameworks/base/media/java/android/media/AudioSystem.java:943)（AudioSystem.java:943-946）、`AudioDeviceInfo.TYPE_BLE_HEADSET/TYPE_BLE_SPEAKER`（AudioService.java:5148-5150）。
>
> **不在本树的是**：mainline 模块 `packages/modules/Bluetooth`（13+ 取代经典蓝牙应用）、`LeAudioCodecConfig`（13+ LC3 协商）、`bta/le_audio/` 完整 native 状态机组（13+）、BASS/Broadcast（14+）、AIDL `IBluetoothLe.aidl`（14+）。原稿"LE Audio Profile 栈为 Android 13+ 才有"的说法按本树更正。

### 14.3.1 本树存在的 LE Audio 代码（12L）

**① HAL 接口层**：[`le_audio_software.cc`](system/bt/audio_hal_interface/le_audio_software.cc)（`system/bt/audio_hal_interface/`）

- 使用 `hardware/interfaces/bluetooth/audio/2.1` 的 `SessionType_2_1`：
  - `LE_AUDIO_SOFTWARE_ENCODING_DATAPATH`（:170，source 方向）
  - `LE_AUDIO_SOFTWARE_DECODED_DATAPATH`（:239，sink 方向）
  - （`LE_AUDIO_HARDWARE_OFFLOAD_*` 与 `LE_AUDIO_BROADCAST_*` 会话类型在 types.hal:34-36 有定义，但本文件未使用）
- 通过 `BluetoothAudioSourceClientInterface`/`BluetoothAudioSinkClientInterface`（:39-42 全局单例）连接蓝牙音频 HAL 会话；
- [`LeAudioClientInterface`](system/bt/audio_hal_interface/le_audio_software.h:32)（软件编码路径）暴露 `SetPcmParameters(PcmParameters)`/`SetRemoteDelay(uint16)`/`StartSession()`/`StopSession()`（:45-49）——PCM 参数化接口，**没有** LC3 配置能力。

**② btif 桩**：[`btif_le_audio.cc`](system/bt/btif/src/btif_le_audio.cc)（仅 102 行）

- 定义 `LeAudioClientInterfaceImpl`（回调桥 `ConnectionState`/`GroupStatus` 等），`hardware/bt_le_audio.h` 的 C API 包装；
- 无状态机、无编解码协商、无组管理（Group Stream Management）逻辑。

### 14.3.2 Java 服务层：12L 早期组管理实现（packages/apps/Bluetooth）

[`LeAudioService.java`](packages/apps/Bluetooth/src/com/android/bluetooth/le_audio/LeAudioService.java) 已实现组（CIG/组流）雏形：

- `mDeviceGroupIdMap: Map<BluetoothDevice, Integer>`（:76）设备→组 ID 映射；`mGroupIdConnectedMap`（:77）组连接状态；`mActiveDeviceGroupId = LE_AUDIO_GROUP_ID_INVALID`（:78）。
- `connect()`（:218 起）按 `getGroupId(device)` 取组 ID，`sm.sendMessage(LeAudioStateMachine.CONNECT, groupId)`（:232）并"Connect other devices from this group"（:235 注释）。

**链路缺口（12L 实况）**：native 栈侧只有 102 行 `btif_le_audio.cc` 桩（无 BTA 层、无编解码协商），且全树无 liblc3；Audio 侧 `BtHelper` 无 `mLeAudio`/LeAudio 事件分支（grep 无匹配）——即 Java 服务存在但软编码数据面与 audio 路由集成**未完成**，12L 不可用（与 AOSP 12L 实验性状态一致）。

### 14.3.3 概念速览（版本限定，非本树实现）

- **LE Audio**（Bluetooth Core 5.2+）：基于 ISO 同步通道（CIS/unicast、BIS/broadcast）的音频框架，强制 LC3 编解码，支持多设备同步、音频共享。
- **Android 13+ 的完整栈**（不在本树）：mainline `packages/modules/Bluetooth`、`LeAudioCodecConfig`（LC3 16/24/32/48kHz 协商）、`bta/le_audio/` native 状态机组（UnicastStateMachine/GroupStreamManager）、TMAP 角色协商；14+ 再加 BASS/Broadcast 与 AIDL `IBluetoothLe`。
- 12L 的 `audio_hal_interface/le_audio_software.cc` 即为上述栈预留的 HAL 数据通道底座（SessionType_2_1 在 2.1 HIDL 中引入本身就是为了 LE Audio 软件路径）。

### 14.3.4 本树产品的实际约束

- 车载 msmnile_gvmq 的 audio_policy_configuration（msmnile_au）中**没有** BLE 相关 devicePort（见 [11.5](../11_Vendor_Layer/11_11.5_car_audio_configuration.xml-AAOS车载配置.md)）——常量存在但产品策略未配置 BLE 路由。
- 结论：本产品 12L 主线的蓝牙音频 = A2DP + SCO/HFP + HearingAid（Classic BT 与 LE 助听），**LE Audio 不可用**（Java 服务与设备常量存在，但无 liblc3、无 native 状态机、无 BtHelper 集成、无策略路由）；LE Audio 相关深度内容见 [14.7](14_14.7_LE_Audio_Profile深度解析.md)/[14.8](14_14.8_LC3编码参数与配置.md)/[14.9](14_14.9_LE_Audio广播音频Broadcast_Audio.md) 兼容入口。
