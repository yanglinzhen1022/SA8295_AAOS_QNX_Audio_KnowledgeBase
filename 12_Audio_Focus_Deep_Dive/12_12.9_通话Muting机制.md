## 12.9 通话Muting机制

> [← 上一个](12_12.8_Audio_Focus全栈调用链.md) | [← 返回12章](README.md) | [返回导航](../README.md) | [下一个 →](12_12.10_FadeOutManager深度解析.md)

---

通话Muting机制是Audio Focus框架级执行的第三条路径（Duck/FadeOut/Mute），专门处理来电(RING)和通话(CALL)场景下对媒体/游戏播放的静音。与Duck的音量衰减和FadeOut的淡出不同，Mute直接将播放器音量设为0。

### 12.9.1 通话Muting触发架构

```mermaid
flowchart TB
    A[电话/铃声栈 requestAudioFocusForCall<br>clientId=IN_VOICE_COMM_FOCUS_ID] --> B[mRingOrCallActive=true\nMFC:920-922]
    B --> C{ENFORCE_MUTING_FOR_RING_OR_CALL?}
    C -->|true| D[runAudioCheckerForRingOrCallAsync<br>true]
    C -->|false| E[不执行Muting]
    D --> F[延迟100ms<br>RING_CALL_MUTING_ENFORCEMENT_DELAY_MS]
    F --> G{再次检查mRingOrCallActive}
    G -->|true| H[mutePlayersForCall<br>USAGES_TO_MUTE_IN_RING_OR_CALL]
    G -->|false| I[unmutePlayersForCall]

    J[IN_VOICE_COMM_FOCUS_ID abandonAudioFocus<br>MFC:1086-1088] --> K[mRingOrCallActive=false]
    K --> L[runAudioCheckerForRingOrCallAsync<br>false]
    L --> M[unmutePlayersForCall]
```

### 12.9.2 ENFORCE_MUTING_FOR_RING_OR_CALL开关

源码位置：[`ENFORCE_MUTING_FOR_RING_OR_CALL` :84](frameworks/base/services/core/java/com/android/server/audio/MediaFocusControl.java:84)（12L 实际行号）

```java

```

| 开关值 | 行为 | 影响 |
|--------|------|------|
| true(默认) | 来电/通话时自动静音USAGE_MEDIA和USAGE_GAME播放器 | 媒体音乐在来电时被静音 |
| false | 不执行框架级Muting，完全依赖App自行响应AUDIOFOCUS_LOSS | 旧版本兼容模式 |

### 12.9.3 USAGES_TO_MUTE_IN_RING_OR_CALL

源码位置：[`USAGES_TO_MUTE_IN_RING_OR_CALL` :819](frameworks/base/services/core/java/com/android/server/audio/MediaFocusControl.java:819)（12L 实际行号）

```java
// MediaFocusControl.java:818-820（逐字摘录）
private final static int[] USAGES_TO_MUTE_IN_RING_OR_CALL =
    { AudioAttributes.USAGE_MEDIA, AudioAttributes.USAGE_GAME };
```

| Usage | 值 | 场景 | Muting行为 |
|-------|-----|------|-----------|
| USAGE_MEDIA | 1 | 音乐播放 | 来电/通话时静音 |
| USAGE_GAME | 12 | 游戏音效 | 来电/通话时静音 |

**不在Muting列表中的Usage：**

| Usage | 场景 | 原因 |
|-------|------|------|
| USAGE_NOTIFICATION | 通知 | 通话中仍需通知 |
| USAGE_VOICE_COMMUNICATION | 语音通信 | 即通话本身 |
| USAGE_ASSISTANCE_NAVIGATION_GUIDANCE | 导航 | 通话中仍需导航 |
| USAGE_ALARM | 闹钟 | 闹钟不应被静音 |
| USAGE_ASSISTANT | 助手 | 助手可能需要响应 |
| USAGE_SAFETY/EMERGENCY | 安全/紧急 | 绝对不能静音 |

### 12.9.4 runAudioCheckerForRingOrCallAsync详解

源码位置：[`runAudioCheckerForRingOrCallAsync` :1114](frameworks/base/services/core/java/com/android/server/audio/MediaFocusControl.java:1114)（12L 实际行号；调用点 :1048）

```java
// MediaFocusControl.java:1114-1135（逐字摘录）
private void runAudioCheckerForRingOrCallAsync(final boolean enteringRingOrCall) {
    new Thread() {
        public void run() {
            if (enteringRingOrCall) {
                try {
                    Thread.sleep(RING_CALL_MUTING_ENFORCEMENT_DELAY_MS);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            }
            synchronized (mAudioFocusLock) {
                // since the new thread starting running the state could have changed, so
                // we need to check again mRingOrCallActive, not enteringRingOrCall
                if (mRingOrCallActive) {
                    mFocusEnforcer.mutePlayersForCall(USAGES_TO_MUTE_IN_RING_OR_CALL);
                } else {
                    mFocusEnforcer.unmutePlayersForCall();
                }
            }
        }
    }.start();
}
```

**关键设计要点：**

| 要点 | 说明 |
|------|------|
| 异步线程 | 避免在焦点请求的关键路径上阻塞 |
| 延迟100ms | 给App时间自行暂停播放，避免框架与App双重操作 |
| 重新检查 | 延迟后再次检查mRingOrCallActive，防止状态已变 |
| 持有mAudioFocusLock | 与焦点栈操作互斥，保证一致性 |
| enteringRingOrCall=false时不延迟 | 退出通话时立即unmute |

### 12.9.5 mutePlayersForCall源码解析

源码位置：[`mutePlayersForCall` :629](frameworks/base/services/core/java/com/android/server/audio/PlaybackActivityMonitor.java:629)（12L 实际行号）

```java
// PlaybackActivityMonitor.java:632-663（逐字摘录，省略 DEBUG 日志段）
public void mutePlayersForCall(int[] usagesToMute) {
    synchronized (mPlayerLock) {
        final Set<Integer> piidSet = mPlayers.keySet();
        final Iterator<Integer> piidIterator = piidSet.iterator();
        // find which players to mute
        while (piidIterator.hasNext()) {
            final Integer piid = piidIterator.next();
            final AudioPlaybackConfiguration apc = mPlayers.get(piid);
            if (apc == null) {
                continue;
            }
            final int playerUsage = apc.getAudioAttributes().getUsage();
            boolean mute = false;
            for (int usageToMute : usagesToMute) {
                if (playerUsage == usageToMute) {
                    mute = true;
                    break;
                }
            }
            if (mute) {
                try {
                    sEventLogger.log((new AudioEventLogger.StringEvent("call: muting piid:"
                            + piid + " uid:" + apc.getClientUid())).printLog(TAG));
                    apc.getPlayerProxy().setVolume(0.0f);
                    mMutedPlayers.add(new Integer(piid));
                } catch (Exception e) {
                    Log.e(TAG, "call: error muting player " + piid, e);
                }
            }
        }
    }
}
```

**执行流程：**

1. 遍历所有活跃播放器(mPlayers)
2. 检查每个播放器的Usage是否在usagesToMute中
3. 匹配则调用`PlayerProxy.setVolume(0.0f)`直接静音
4. 将piid加入mMutedPlayers集合

### 12.9.6 unmutePlayersForCall源码解析

源码位置：[`unmutePlayersForCall` :668](frameworks/base/services/core/java/com/android/server/audio/PlaybackActivityMonitor.java:668)（12L 实际行号）

```java
// PlaybackActivityMonitor.java:668-690（逐字摘录，省略 DEBUG 日志段）
public void unmutePlayersForCall() {
    synchronized (mPlayerLock) {
        if (mMutedPlayers.isEmpty()) {
            return;
        }
        for (int piid : mMutedPlayers) {
            final AudioPlaybackConfiguration apc = mPlayers.get(piid);
            if (apc != null) {
                try {
                    sEventLogger.log(new AudioEventLogger.StringEvent("call: unmuting piid:"
                            + piid).printLog(TAG));
                    apc.getPlayerProxy().setVolume(1.0f);
                } catch (Exception e) {
                    Log.e(TAG, "call: error unmuting player " + piid + " uid:"
                            + apc.getClientUid(), e);
                }
            }
        }
        mMutedPlayers.clear();
    }
}
```

**恢复特点：**

| 特点 | 说明 |
|------|------|
| 直接恢复到1.0 | 无渐变，瞬间恢复 |
| 仅恢复mMutedPlayers | 只恢复被Mute静音的播放器 |
| 播放器可能已不存在 | apc==null时跳过，不报错 |
| clear()清空记录 | unmute后mMutedPlayers为空 |

### 12.9.9 Mute vs Duck vs FadeOut对比

| 维度 | Mute | Duck | FadeOut |
|------|------|------|---------|
| 触发场景 | 来电/通话 | 导航/助手获得焦点 | 媒体失去焦点(非Duck) |
| 音量操作 | setVolume(0.0f) | applyVolumeShaper(DUCK) | applyVolumeShaper(FADEOUT) |
| 衰减量 | 100%(静音) | 12L 固定≈14dB（-35dB 强Duck 为 14+，不在本树） | 渐变到0 |
| 恢复方式 | setVolume(1.0f)瞬间 | applyVolumeShaper(REVERSE) | applyVolumeShaper(REVERSE) |
| 延迟触发 | 100ms | 无延迟 | 无延迟 |
| 执行器 | PAM直接执行 | DuckingManager | FadeOutManager |
| 管理集合 | mMutedPlayers | mDuckers（DuckingManager 字段） | mFadedPlayers |
| ENFORCE开关 | ENFORCE_MUTING | ENFORCE_DUCKING | ENFORCE_FADEOUT |
| 是否有Limbo | 否 | 否 | 是(2s延迟) |

### 12.9.10 RING_CALL_MUTING_ENFORCEMENT_DELAY_MS设计

```java
// MediaFocusControl.java:814（逐字摘录）
private static final int RING_CALL_MUTING_ENFORCEMENT_DELAY_MS = 100;
```

**100ms延迟的设计意图：**

1. **App优先响应**：App收到AUDIOFOCUS_LOSS后通常自行暂停，100ms给App处理时间
2. **避免双重操作**：如果App已暂停，框架Mute不会产生额外效果
3. **兜底保护**：如果App未响应Loss(如bug或延迟)，框架确保静音
4. **不能太长**：100ms足够短，不会让用户听到明显的媒体播放

### 12.9.11 通话Muting与AudioMode的关系

**勘误（12L 实况）**：`mRingOrCallActive` **不由 setMode 置位**——它由 clientId 为 `IN_VOICE_COMM_FOCUS_ID` 的焦点请求置位（MFC:921-923），在对应 abandon 时复位（:1086-1088）。电话/铃声栈经 `AudioManager.requestAudioFocusForCall`（AudioManager.java:4369-4382，带 `AUDIOFOCUS_FLAG_LOCK`）发起。AudioMode（RINGTONE/IN_CALL/IN_COMMUNICATION）与此机制无直接联动。关系概览：

| 请求方 clientId | mRingOrCallActive | Muting行为 |
|----------------------|-------------------|-----------|
| IN_VOICE_COMM_FOCUS_ID（电话/铃声） | true（请求时置位） | 执行mute |
| IN_VOICE_COMM_FOCUS_ID abandon | false（abandon复位） | 执行unmute |
| 其他 clientId（含 VoIP App） | 不变（通常false） | 不触发通话Muting；VoIP 走标准焦点Loss传播 |

### 12.9.12 边界条件

| 条件 | 处理 |
|------|------|
| 快速进入/退出通话 | 延迟后重新检查mRingOrCallActive，可能跳过mute |
| 播放器在Mute期间结束 | unmute时apc==null，跳过 |
| 新播放器在通话中启动 | mutePlayersForCall遍历mPlayers时会覆盖新播放器 |
| 同一App多个播放器 | 按piid独立管理，每个都静音 |
| ENFORCE_MUTING=false | 完全跳过，依赖App自行响应 |
